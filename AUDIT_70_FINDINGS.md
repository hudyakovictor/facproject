## P0 — Дефекты, искажающие результат

### D1. NaN получает статус `elevated` (A45, A48, A49, A50)
`calibrated_score` при `value=NaN`: все сравнения возвращают `False`, поток доходит до `else: elevated`.

```
value=NaN  -> z=nan  status=elevated      # ложная аномалия
value=+Inf -> z=inf  status=elevated
value=-Inf -> z=-inf status=within_calibration_noise
```

Не теоретический: sidecar-калибровка не содержит alpha (A40), поэтому `alpha_id_l2` и `alpha_exp_l2` = NaN **на каждой паре**. Значение утекает в `engine.py:213-214`, где `alpha_exp_l2 == 'elevated'` управляет присвоением `expression_dominated`.
**Фикс**: в начале `calibrated_score` возвращать статус `not_measurable` при нефинитном `value`.

### D2. Половина зон атласа не может дать измерение (A11, A20)
`mesh_zone_indices.json`: 11 зон из 23 имеют < 4 вершин при пороге `dense_mesh_pair` в 4 точки.

```
chin 1 · temporal_L/R 2 · cheek_soft_L/R 2 · ligament_orbital_L/R 2
ligament_zygomatic_L/R 2 · jaw_angle_L/R 3        -> МЁРТВЫЕ
jaw_L/R 8                                          -> слабые
Рабочих зон: 12 из 23
```
Подбородок, виски, связки и углы челюсти молча выпадают из анализа. Это ключевые костные структуры.

### D3. Двойной учёт крыльев носа (A14, A18)
`nose_wing_L` (289) и `nose_wing_R` (300) — **полные подмножества** `nose_bridge_tip` (754). Проверено: `wing_L ⊆ bridge_tip == True`. 589 вершин участвуют в двух зонах, вес носа завышен вдвое. Всего 11 пересекающихся пар зон.

### D4. Нормативный атлас поз не читается кодом (A28, A29)
`AGENTS.md:92` объявляет `pose_policy_v3_9bins.csv` единственной нормативной политикой. Ни один рантайм-модуль его не загружает — совпадения только в `STATUS_AUDIT.py` (строка статуса) и генераторе другого CSV. Политика видимости зон по ракурсам фактически не применяется.

### D5. Инверсия конвенции yaw между версиями атласа [исправлено] (A22, A27)
Первичный вывод «v3 отключает политику» **опровергнут**: распределение статусов идентично (132 primary / 16 support / 16 limited / 16 exclude). Реальный дефект другой — 96 из 180 ячеек инвертированы:

```
A01  yaw:    -60    -40    -25 ...  25     40     60
old:      exclude limited support   primary primary primary
v3 :      primary primary primary   support limited exclude
```
Зеркальное отражение: какая сторона лица считается видимой при `+yaw`. Два атласа лежат рядом, ни один не подключён — при подключении не того результат инвертируется.

### D6. `balanced_reference` принимает одного человека (A52)
Функция задумана как «равный вес на персону» против доминирования одного участника. При входе с 1 человеком возвращает валидный референс (`dataset_count: 1`) вместо отказа. Смежная `balanced_person_threshold` корректно требует ≥3. Калибровка может незаметно опереться на одного субъекта.

### D7. Порог FDR не соответствует ТЗ (A47)
ТЗ п.9 требует FDR ≤ 0.05, `apply_pair_fdr` и `apply_zone_fdr` используют `q_threshold=0.10`. Сама BH-процедура математически корректна (A46: монотонность, 0/100 ложных, 20/20 истинных, пустой вход).

## P1 — Существенное

### D8. Хеши считаются, но не проверяются (A89, A90)
`code_hash`, `config_hash`, `model_hash` вычисляются в `stage1/engine.py` и пишутся в манифест. В `run_preflight.py` слово `hash` не встречается ни разу. ТЗ п.11 (блокировка запуска при расхождении) не выполнен — подмена калибровки не будет замечена.

### D9. Порядок колонок CSV нестабилен [исправлено] (A80, A81)
Первичный вывод «поля теряются» **опровергнут**: `write_csv` корректно объединяет ключи всех строк (`a,b` + пустые ячейки). Реальный дефект — порядок заголовка зависит от порядка ключей первой строки:
```
запуск1: a,b     запуск2: b,a     стабилен: False
```
Диффы между прогонами становятся нечитаемыми. ТЗ п.14 обоснован.

### D10. Модель кожи — одноклассовая, «силикон» не измеряет (A67, A68, A72, A76, A77)
`model_quality_gate.json`: `fit_real_n=402`, пороги `q95/q99` — перцентили распределения **реальной** кожи, агрегация `median_z_top20`.
Нюанс: отбор 40 метрик **валидировался** на силиконовых пробах (`sil_catch_q95` есть у 40/40, факторы `F09_silicone_sensitivity`, `F10_strict_silicone_catch`). Но финальный порог — one-class по реальной коже.
Итог: score измеряет **отклонение от нормы кожи**, а не вероятность силикона. Причиной отклонения может быть сжатие, грим, освещение, плохое качество. UI-спека обещает «FFT Regularity Peak (детекция силикона)» и `H1 (силиконовая маска/дипфейк)` — заявление сильнее данных.

### D11. `ZONE_WEIGHTS` названы костными, но координатные (A30)
Ключи `x_low_low`…`x_high_high` — сетка 3×3 по координатам, что честно указано в `build_coordinate_zone_map` («Coordinate zones are not anatomical labels»). Но комментарий над `ZONE_WEIGHTS` в `core.py:327` гласит `# Bone zones (most stable, highest weight)`. Прямое противоречие в одном файле.

### D12. Legacy-ракурсы не сматчатся (A98)
6 из 9 бинов имеют другие имена: `left_threequarter_light` ↔ `left_light` и т.д. Совпадают только `frontal`, `left_profile`, `right_profile`. Без таблицы соответствия 6223 гипотезы останутся `pending` навсегда.
