# Executive summary

## Краткий ответ

**Нет: в текущем виде результаты DEEPUTIN нельзя предъявлять в суде или журналистском расследовании как надёжное доказательство подмены личности, маски, силикона либо хирургического вмешательства.** Их можно использовать как **систему технического триажа**: для поиска пар, которые следует перепроверить вручную и независимыми методами.

Главная проблема не в том, что Kabsch, BH или 3DDFA сами по себе «неправильны». В коде действительно есть несколько продуманных защит: сравнение только внутри pose bin, residual-pose gate, intersection видимости, robust Kabsch, identity-only канал, equal-person calibration, LOPO sensitivity, quality/calibration/pose downgrades и безопасные формулировки Stage 3. Несколько подозрительных на первый взгляд мест после чтения полного пути оказываются корректно ограниченными: текстура не используется как identity evidence; cross-bin не меняет primary residual; отсутствующая alpha не превращается в ноль; chronology-aligned координаты не подменяют primary raw-object-normalized канал.

Однако цепочка доказательности нарушается в других, менее очевидных местах:

1. **P0 — статистическая значимость не управляет детекцией.** FDR вычисляется уже после формирования статусов и не участвует в `evidence_state`/`change_points`. Более того, p-value для `p95_point_z` основан на независимых стандартно-нормальных точках, хотя точки зависимы, z-score эмпирический, а 81% пар имеют менее 20 калиброванных точек. Поэтому наличие BH в артефакте не означает контроля FDR для публичных кандидатов.
2. **P0 — калибровочный matched-null зависит от порядка обработки.** Глобальный `_use_count` изменяет подбор калибровочных кадров между парами; при resume модель создаётся заново, поэтому продолженный прогон может отличаться от непрерывного. Заявленный hard cap также не является hard cap: когда «свежих» кадров нет, код снова выбирает из исчерпанных кандидатов.
3. **P0 — expression gate фактически не гейтит выражение.** `_pair_qc_decision()` исключает только отсутствие QC, а `expression_gate()` всегда возвращает `accepted=True`. Основной статус берётся из identity+expression landmarks, а descriptor channel способен повысить статус до `coherent_jump_candidate`. Identity-only канал рассчитывается, но не является обязательным условием кандидата.
4. **P1 — angle-noise subtraction декоративен.** Компенсированные значения сохраняются в строке, но калибровка, статус, chronology и evidence продолжают использовать сырые значения. Следовательно, заявленная компенсация pose leakage не исправляет вывод.
5. **P1 — chronology thresholds не валидированы внешним null.** Пороги 4.5/5.5, 60/180 дней, coherence/fraction и CUSUM заданы вручную; rate-null строится из самих исследуемых evidence-пар. Это круговая, потенциально загрязнённая база.
6. **P1 — Stage 1 проверяет внутреннюю согласованность, не точность реконструкции.** Reprojection сравнивает два выхода той же модели. Это полезный software invariant, но не оценка ошибки 3D относительно ground truth и не защита от pose/lighting bias 3DDFA.
7. **P1 — публичная визуализация может усиливать впечатление.** В motion maps длина стрелок нормируется по максимуму каждой пары, а top-40 выбираются по raw `p95_point_z`, включая ограниченные пары. Небольшое движение может визуально выглядеть столь же крупным, как большое.

## Допустимое использование сейчас

- **Можно:** diagnostic triage, ручная очередь проверки, поиск кадров с нестабильной реконструкцией, формирование гипотез.
- **С оговорками:** `ldm134_rmse`, point-motion и dense mesh как технические измерения внутри узкого pose/quality/calibration domain.
- **Нельзя:** вывод «другой человек», «маска», «силикон», «операция»; количественное утверждение о вероятности такого события; утверждение о контролируемом FDR среди опубликованных change candidates.

## Что необходимо до доказательного применения

Минимальный путь: (1) заморозить deterministic matched-null без глобального состояния; (2) сделать expression/quality/pose applicability реальными preregistered gates; (3) построить эмпирический subject-clustered null для итогового pair score; (4) определить единственную primary hypothesis per pair и применить cluster-aware multiple testing до evidence mapping; (5) провести внешнюю валидацию на большем числе людей, камер, эпох, поз и известных negative/different-person controls; (6) оценить повторяемость Stage 1 и ground-truth 3D/landmark error; (7) публиковать effect size, uncertainty и abstention, а не только статус.

**Итоговая оценка доверия:**

| Уровень | Оценка |
|---|---|
| Корректность программных контрактов | Средняя/выше средней |
| Воспроизводимость научного score | Низкая до исправления matched-null |
| Калибровочная переносимость | Низкая (7 персон недостаточно) |
| Контроль ложных обнаружений | Низкий; текущий BH диагностический |
| Пригодность для triage | Средняя при ручной проверке |
| Пригодность как доказательство причины/личности | Недостаточная |

# 1. Метод и границы аудита

## 1.1 Выполнено

- Прослежены data paths Stage 1 → loaders → pair planning → core/motion/descriptors/mesh/texture → calibration → chronology → corroboration → evidence → Stage 2B/Stage 3.
- Проверены реальные места использования результатов, а не только наличие функций.
- Запущены unit/regression tests без весов:
  - **417 passed, 2 failed, 10 subtests passed**.
  - Падения: тесты `ApiReportTests` ожидают старый `report_data.json`, тогда как API теперь требует `report_meta.json + report_sections/`. Это контрактный дрейф тестов/API, не научная валидация.
- Проверены comments/docs против фактического control flow.

## 1.2 Не выполнено из-за отсутствующих данных

Следующие критерии ТЗ **не могут считаться закрытыми**:

- повторный inference одного фото и оценка repeatability;
- 943-frame calibration reproduction;
- empirical/permutation null;
- threshold sensitivity ±20%;
- perturbation ±1 px / ±2 px;
- известные same/different-person ground-truth ROC/PR/calibration;
- проверка корреляций с годом, камерой, JPEG, освещением на исходном архиве.

Поэтому это **полный статический методологический аудит**, но не финальная эмпирическая сертификация.

## 1.3 Шкала критичности

- **P0:** нарушает воспроизводимость либо позволяет публичному кандидату возникнуть без заявленного статистического/методологического контроля.
- **P1:** существенно ограничивает валидность или создаёт высокий риск ложной интерпретации.
- **P2:** локальная неоднозначность, документационный/визуальный риск или улучшение прозрачности.

# 3. Stage 1 — извлечение признаков

## 3.1 Что сделано корректно

1. **Один inference на фото.** Forward hook проверяет ровно один вызов `net_recon`; повторный inference запрещён (`app6/stage1/reconstruction.py:203-232`).
2. **Alpha channels захватываются до преобразований** и разделяются штатным `split_alpha` (`:237-247`).
3. **Сохраняются object, normalized, identity-only и chronology representations.** Stage 2 явно выбирает raw object-normalized coordinates, а chronology-aligned не подменяет primary (`app6/stage2/loaders.py:103-111`). Это корректное исправление потенциально опасной ошибки пространства.
4. **Видимость — intersection front-facing и renderer visibility**, а не «все landmarks видимы» (`reconstruction.py:315-321`).
5. **Нефинитные массивы и shape mismatch fail closed** в loaders.

## 3.2 Ограничения достоверности

### F-10 — reprojection не валидирует реальную 3D-точность (P1)

`vertices_image[idx]` сравниваются с `results["ldm106/134"]` того же forward path (`reconstruction.py:294-311`). Это хороший тест внутренней связности vertex indices/projection, но обе величины порождены одной моделью. Общий систематический bias относительно настоящей анатомии останется невидимым.

**Рекомендация:** переименовать gate в `internal_reprojection_consistency`; отдельно измерить NME/pixel/mm error на внешнем ground truth, стратифицированном по yaw/pitch/roll, освещению, разрешению, возрасту снимка и expression.

### Pose estimation

Углы — параметры 3DDFA, но в репозитории нет внешней оценки angular MAE. Пер-bin gate уменьшает различия внутри пар, однако неизвестно, одинаково ли ошибается pose estimator на VHS/сканах и современных фото.

**Граница применимости:** pose angles допустимы для внутреннего binning/gating после empirical error study; не допустимы как физически точные градусы без такой проверки.

### Landmark repeatability

Нет теста повторного декодирования/inference с controlled augmentations. Unit tests проверяют массивы и синтетические transforms, но не реальную повторяемость сети.

**Нужно:** test-retest на одинаковом фото после JPEG recompression, resize, ±brightness, ±2° roll; отчёт median/p95 pixel и normalized 3D error per landmark/per pose.

### F-11 — эвристическая confidence (P1)

`detection_confidence` вычисляется из доли bbox в изображении, а не из RetinaFace score (`app6/stage1/engine.py:512-523`). Затем это значение участвует в quality stratification. Большое лицо не обязательно надёжно, а маленькое — ненадёжно; framing/era могут стать скрытым confounder.

**Рекомендация:** назвать `face_area_heuristic`, не `detection_confidence`; не использовать как calibrated confidence. Получать native detector score либо валидировать proxy отдельно.

### Expression features

`corner_lift_ioc` и `jaw_open_ratio` — разумные interpretable proxies, но индексы и пороги не валидированы на размеченной выборке. `jaw_open_degree = abs(alpha_exp[0])*100` прямо обозначен heuristic и не должен читаться как градусы.

### Texture / illumination

Stage 1 сохраняет богатые texture/quality channels, но не выполняет photometric standardization, достаточную для сравнения эпох. Это не баг, если texture остаётся diagnostic/visualization. В текущем evidence packet именно так и сделано.

## 3.3 Оценка Stage 1

**Software extraction:** использовать можно.  
**Forensic measurement accuracy:** пока не доказана.  
**Главная граница:** успешный reprojection gate означает «артефакты модели согласованы между собой», а не «3D лицо восстановлено без bias».

# 4. Stage 2 — пары, alignment, calibration и аномалии

## 4.1 Pose binning и pair legality

Плюсы:

- primary сравнения только внутри одного bin;
- residual axis-specific pose gate;
- профили разделены на 10° sub-bins;
- right profile с SNR3=0 не проходит обычный gate;
- pair planner детерминирован по датам/sequence.

Ограничения:

- thresholds в `pose_gate_v2.csv` описаны как полученные на конкретном calibration set; переносимость на main archive не доказана;
- `frontal` допускает yaw gap до 12°, что требует empirical residual analysis, особенно у границ;
- бин — не гарантия одинаковой self-occlusion/lighting.

**Вердикт:** binning — пригодный gate, но не normalization и не доказательство comparability.

## 4.2 Kabsch alignment

Iteratively trimmed rigid Kabsch без scale — методологически разумен для homologous 3D landmarks. Reflection исправляется, trim ограничен, fit diagnostics сохраняются.

Риски:

- anchors определяются на геометрии A и visibility intersection; сравнение направленное;
- при 30 точках 15% trim оставляет небольшой effective support;
- alignment способен частично поглотить диффузное изменение, а per-photo RMS normalization удаляет global scale;
- uncertainty rotation/translation не распространяется в downstream z.

**Рекомендация:** bootstrap landmarks для CI residual; symmetry check `A→B` vs `B→A`; sensitivity к trim 0/10/15/20%; отдельно фиксировать, какие виды изменения принципиально уничтожаются normalization/alignment.

## 4.3 F-03 — expression gate фактически выключен (P0)

Заявление в docstring `_pair_qc_decision()` о том, что пара исключается при выражении, не соответствует коду: после проверки наличия QC функция безусловно возвращает `applicable=True` (`app6/stage2/engine.py:148-173`). `expression_gate()` также всегда возвращает `accepted=True` (`app6/stage2/expression_pair_gate.py`). Поле `accepted` лишь записывается в summary и не гейтит processing.

Далее:

- main point-motion использует identity+expression `ldm134`;
- status берётся из `motion_score134`;
- descriptor jump на identity+expression landmarks может повысить статус до `coherent_jump_candidate` (`engine.py:321-335`);
- identity-only RMSE вычисляется, но не является обязательной корроборацией.

Таким образом, улыбка/челюсть/мягкие ткани могут сформировать кандидата даже при отсутствии identity-only подтверждения.

**Исправление:** preregister одно из двух:

1. fail-closed expression applicability gate; либо
2. разрешать пару, но кандидат возможен только при elevated identity-only primary и низком expression influence, с отдельным expression-matched empirical null.

## 4.4 F-02 — matched-null stateful и невоспроизводим (P0)

`CalibrationModel._nearest()` использует глобальный `self._use_count`. Каждая основная пара меняет выбор calibration frames для следующих пар (`app6/stage2/calibration.py:130-149`). Это создаёт:

- зависимость score от порядка pair specs;
- зависимость от числа ранее обработанных пар;
- различие между uninterrupted и resumed run: при resume `CalibrationModel` создаётся заново, `_use_count` обнуляется, а обработанные пары пропускаются;
- несоответствие комментария hard cap: если `fresh` пуст, код оставляет исходный список и снова выбирает исчерпанные кадры.

Это не просто performance issue: matched 95th percentile входит в threshold `calibrated_score`, поэтому меняется статус.

**Исправление P0:** matched-null должен быть чистой функцией `(pair, calibration snapshot, seed/policy version)`. Подбор можно делать deterministic nearest-k per person с фиксированным tie-break, без глобального mutable state. Если нужен global assignment, его следует решить один раз до scoring, сохранить и включить в run hash/checkpoint.

## 4.5 Калибровка на 7 людях и point support

Equal-person median-of-quantiles лучше, чем pooling всех кадров. LOPO sensitivity — полезная диагностика. Но семь людей не представляют вариативность лица, возраста, пола, этничности, камер, выражений и эпох. Внутрисубъектные пары также не независимы.

Для per-landmark reference требуется лишь `count>=7`, что может означать множество зависимых пар очень малого числа субъектов. При `<~20` calibrated points p95 нестабилен; при 81% таких пар итоговая статистика в основном находится за пределами заявленного full-support domain.

**Граница:** `<20` точек — не просто «чуть меньше уверенности». Для p95/order-stat p-value это другой статистический объект. Такие пары должны abstain для inferential status, а не получать single-z fallback.

## 4.6 F-04 — angle-noise subtraction не влияет на решение (P1)

`subtract_angle_noise()` создаёт `*_angle_compensated`, но:

- `calibrated_score()` уже выполнен на raw metrics до subtraction;
- point-motion/status используют raw coordinates;
- chronology использует raw `p95_point_z`;
- evidence mapping не смотрит compensated fields.

`engine.py:313-340` показывает порядок явно. Следовательно, модуль — annotation, а не compensation.

Дополнительно вычитание расстояний `max(0, observed-noise)` само по себе не обосновано: независимые error variances обычно комбинируются не линейным вычитанием RMSE. Лучше моделировать metric conditional on pose delta либо использовать matched empirical null без арифметического subtraction.

## 4.7 F-01/F-05 — FDR и p-values (P0/P1)

### Что корректно

Реализация BH как алгоритма сортировки/монотонных q-values корректна.

### Что некорректно методологически

1. `p95_point_z` переводится в p-value через binomial order statistic при iid `|N(0,1)|`. Но landmark z:
   - построены из estimated median/MAD;
   - имеют разные denominators и sample counts;
   - пространственно зависимы;
   - после общего Kabsch особенно зависимы;
   - проходят selection по visibility.
2. При `<20` points p95 заменяется p-value одиночного normal z, хотя само значение остаётся p95. Это не валидная смена null.
3. `n_eff=photo_count//2` не выведен из covariance/cluster design. Умножение q на `m/n_eff` — ad hoc penalty, не стандартная cluster-aware FDR procedure.
4. FDR запускается **после** persistence, chronology и corroboration, затем не используется в evidence mapping (`engine.py:372-419`).
5. Descriptor families, mesh metrics, zone metrics, chronology flags и selection лучшего канала не включены в одну заранее объявленную hypothesis family.

**Ключевой вывод:** `mt_q_value` можно показывать только как experimental diagnostic. Нельзя писать, что FDR публичных change candidates контролируется на 0.05.

**Исправление:** empirical subject-clustered null/permutation для единственного preregistered pair score; затем resampling-based maxT/Westfall–Young либо иерархический FDR (pair → family → location), с cluster/block permutations по фото/сессии/персоне. Evidence candidate должен формироваться после этой процедуры.

## 4.8 Chronology и rate flags

`rate = p95_z × coherence / sqrt(days)` — эвристический ranking score, не биологическая модель. Пороговые комбинации 4.5/5.5, 60/180 дней, 0.35–0.50 coherence, 0.15–0.18 significant fraction и rate-z 3/3.5 вручную зафиксированы в коде.

Rate reference строится из main evidence rows по каждому pose bin (`chronology.py:55-100`). Если в исследуемом периоде есть реальные изменения или систематический era bias, null загрязнён. При малом N median/MAD и floor 0.05 дают нестабильную семантику.

Термин `rapid_change_candidate` допустим как heuristic diagnostic; «biologically improbable» не подтверждён calibration.

### F-08 — persistence через разрыв (P1)

`Stage2Engine._persistence()` проверяет следующие 1–2 строки в pose bin, но не требует `current.photo_b == next.photo_a` (`engine.py:462-470`). После QC/pose skips последовательные обработанные rows могут не образовывать непрерывную цепь. Кандидат может стать `persistent_geometric_change` по несвязанной следующей паре.

**Исправление:** обязательная continuity, совместимость направления/зон, minimum post-change duration и baseline comparison.

## 4.9 Baseline return

В отличие от persistence, baseline-return правильно требует A→B, затем B→C и проверяет противоположность векторов. Но thresholds experimental и не калиброваны. Использовать только diagnostic.

## 4.10 Dense mesh

Плюсы:

- homologous vertices;
- common visibility;
- robust rigid alignment;
- calibration channel и explicit uncalibrated status;
- anatomical zones при наличии index file.

Ограничения:

- identity-only vertices нормализуются отдельно для каждого фото: абсолютный scale недоступен;
- BFM shape лежит в ограниченном model subspace и может отражать prior сети;
- normals берутся из expression-including object mesh, тогда как residual может считаться на identity-only normalized vertices;
- 35k vertices не означают 35k независимых наблюдений.

**Вердикт:** calibrated dense mesh — support/diagnostic, не самостоятельное evidence личности.

## 4.11 Texture descriptors

Код честно помечает: `No pose normalization`. При этом zones, LBP/GLCM/Gabor/frequency/ridge чувствительны к:

- освещению и экспозиции;
- blur/JPEG/scanner;
- масштабу пикселя;
- ракурсу и self-occlusion;
- camera pipeline и эпохе.

Важно: финальный evidence packet относит texture/UV в `visualization_only`, а Stage 3 удаляет `texture_`/`uv_` из public pair projection. Поэтому отсутствие pose normalization **не загрязняет identity evidence напрямую**. Это пример места, которое выглядит как P0 при чтении одного файла, но полный data path снижает риск до P1 diagnostic limitation.

При заявленной корреляции texture-year `r=0.52` texture нельзя использовать для хронологического вывода без era/camera matched null.

## 4.12 Quality gate и era bias

Есть downgrade `quality_limited`, но:

- `quality_gate()`/stratum рассчитывается, однако calibrated references обычно не содержат `::q_`, и тогда движок сознательно откатывается на общий pool;
- resolution-specific `compensate_quality_disparity()` не включён в production engine path;
- quality score может сам зависеть от эпохи и framing;
- низкое качество влияет на доступность points и создаёт informative missingness.

Следует моделировать quality/era/camera как covariates или matched strata, а не только post-hoc downgrade.

# 5. Stage 2B — corroboration и prior leads

## 5.1 Что сделано правильно

- Prior leads не меняют primary thresholds/status; используются для покрытия и отчётности.
- Stage 2B читает evidence states Stage 2 и не должен создавать новые факты.
- Cross-bin rows не входят в primary residual.

## 5.2 F-09 — неполная фильтрация corroboration (P1)

Cross-bin support требует candidate raw status и исключает `quality_limited`, но не исключает явно:

- `calibration_limited`;
- `pose_leakage_limited`;
- date provenance conflict;
- near-duplicate dependence;
- низкий point support;
- отсутствие FDR significance.

Кроме того, «independent source count» считается по строковому `source_group_b`, что не доказывает независимый capture/source chain.

Положительный момент: corroboration status не повышает `evidence_state`. Но публичное слово `corroborated` всё равно может быть переоценено.

**Исправление:** support допускается только из admissible evidence-state, независимого capture event/source, достаточного calibration support и после primary inferential gate. Называть `cross-view consistency`, пока независимость не доказана.

## 5.3 Lead registry / leakage

По текущему data path leads не входят в thresholds. Однако они влияют на attention/report prioritization. Для подтверждающего анализа следует заморозить leads до просмотра новых результатов и различать:

- preregistered hypothesis;
- exploratory lead;
- post-hoc narrative selection.

# 6. Stage 3 — интерпретация и публичный отчёт

## 6.1 Плюсы

- Public status заменяется на `evidence_state`, raw status остаётся metadata.
- Texture/UV fields удаляются из public pair projection.
- Reportable changes ограничены adjacent pairs и allowlist states.
- Narrative прямо говорит, что статус не доказывает подмену/маску/операцию.
- Stage 3 требует completed Stage 2 validation.

## 6.2 F-14 — перезапись provenance downgrade (P1)

На раннем шаге date conflict/near duplicate получают limited evidence state (`engine.py:356-360`). Позже все evidence states пересчитываются только с quality/calibration/pose flags (`:403-407`), и downgrade теряется.

Для date conflict это ловит final validator (`validation.py:35`), поэтому опасный отчёт не публикуется, а весь Stage 2 падает. Это fail-closed, но operationally неверно. Для near duplicate аналогичной проверки evidence-state нет; проверяется только exclusion из chronology.

**Исправление:** единая функция mapping со всеми applicability flags; не присваивать evidence state в двух местах; добавить near-duplicate invariant.

## 6.3 F-13 — motion-map autoscaling (P1)

Stage 3 задаёт `scale=22/maxMagnitude` отдельно для каждой пары. Поэтому максимальная стрелка всегда примерно одного размера. Визуализация показывает направление/паттерн, но скрывает абсолютный effect size.

**Исправление:** общий scale per pose/run, scale bar, raw magnitude и calibration p95; отдельный режим normalized-pattern с явной маркировкой.

## 6.4 F-18 — selection top-40 (P2/P1 interpretation)

Motion maps выбираются по raw `p95_point_z`, не по admissibility/evidence tier. Limited pair может попасть в наиболее заметную часть отчёта. Даже при корректном badge это создаёт salience bias.

**Исправление:** сначала evidence/admissibility strata, затем effect size; limited items — отдельная секция «diagnostic, not reportable».

## 6.5 Narrative accuracy

Фраза «каждый landmark и каждая descriptor family имеет same-person calibration» формально близка к коду, но скрывает sparse support и всего 7 людей. Формулировка «аномальный темп» сильнее, чем позволяет self-normalized heuristic.

Предпочтительно:

- «превысил внутренний эвристический порог»;
- указывать N persons, N independent sessions, calibrated point count;
- показывать q-value только как experimental до empirical calibration;
- рядом с каждым candidate выводить strongest alternative explanation.

# 9. Обязательный план эмпирической валидации

## 9.1 Freeze до просмотра результатов

1. Зафиксировать один primary pair score, например identity-only landmark/mesh score.
2. Зафиксировать gates: pose, expression, quality, minimum support, calibration coverage.
3. Зафиксировать family of hypotheses и correction method.
4. Отделить exploratory descriptors/texture от confirmatory channel.

## 9.2 Calibration design

- Не менее десятков, предпочтительно сотен людей, с независимыми capture sessions.
- Баланс pose/quality/era/camera/expression.
- Same-person positives во времени и different-person hard negatives.
- Отдельный внешний validation set, не используемый для thresholds.
- Cluster unit — person/session/photo, не pair и не landmark.

## 9.3 Null и uncertainty

- Empirical null CDF итогового pair score per pose/quality stratum.
- Block/permutation test на уровне subject/session.
- Bootstrap CI на уровне subjects.
- Calibration plot: nominal p vs empirical false-positive rate.
- Повторить с ±1 px, ±2 px, JPEG, blur, brightness, crop, small pose perturbations.

## 9.4 Sensitivity ±20%

Для каждого threshold сформировать stability table:

`threshold × {0.8, 0.9, 1.0, 1.1, 1.2}` → candidate count, Jaccard candidates, rank correlation, false positives on null, recall on known positives.

Особенно: pose gaps, min points, z 3/3.5/4.5/5.5, coherent fraction, quality 0.35, 60/180 days, CUSUM.

## 9.5 Acceptance targets

До court/journalistic evidence-level использования заранее установить:

- test-retest failure rate;
- per-pose FPR и upper confidence bound;
- external AUROC/AUPRC недостаточно — нужна probability calibration;
- maximum allowed abstention and subgroup disparity;
- no material/identity causal wording без независимого метода.

# 11. Критерии применимости

Результат пары допустим как geometry support только если одновременно:

- Stage 1 прошёл не только structural, но и validated quality gates;
- pose bin и residual pose находятся внутри эмпирически проверенного range;
- expression matched либо identity-only primary подтверждён;
- calibrated point count достаточен;
- calibration stratum имеет достаточно независимых людей/sessions;
- quality/era/camera overlap с calibration подтверждён;
- pair не near-duplicate и date/source provenance приемлем;
- primary empirical p прошёл заранее объявленную multiple-testing procedure;
- effect устойчив к ±1/±2 px и threshold sensitivity;
- визуальная и независимая экспертная проверка не выявила reconstruction failure.

При невыполнении хотя бы одного условия — `diagnostic` или `inconclusive`, но не public change evidence.

# 12. Итоговое заключение

DEEPUTIN содержит зрелые элементы инженерной осторожности и значительно безопаснее простого «сравним две фотографии нейросетью». Код явно различает measurement и verdict, сохраняет provenance, часто abstains и не использует texture как identity evidence. Это сильные стороны.

Но **научная достоверность итогового candidate сейчас ниже инженерной зрелости пайплайна**. Основные причины: невоспроизводимый stateful matched-null, фактически выключенный expression gate, невалидированный p-value/FDR path, слабая репрезентативность calibration и эвристическая chronology. Эти проблемы существуют даже если программа работает без исключений и все unit tests зелёные.

**Финальный ответ на ключевой вопрос:**

- **Как надёжное доказательство в суде — нет.**
- **Как самостоятельное доказательство в журналистском расследовании — нет.**
- **Как технический инструмент поиска пар для дальнейшей независимой проверки — да**, при явной маркировке `diagnostic only`, публикации ограничений и запрете причинных/идентификационных выводов.

Переход к evidence-grade возможен только после исправления P0, эмпирической валидации на независимом расширенном dataset и заранее зарегистрированной статистической процедуры.

# Приложение B — важные места, которые не являются ошибками после полного чтения

1. **Chronology branch в engine не перевёрнут:** `require_temporal_axis()` возвращает `None`, когда ось применима; поэтому ветка `if temporal_axis is None` корректно запускает chronology.
2. **Texture warning не означает утечку в identity evidence:** texture/UV исключены из registered metric channel и public projection.
3. **Cross-bin не меняет primary residual/status:** это secondary annotation, хотя admissibility поддержки нужно усилить.
4. **Missing alpha не становится нулём:** nonfinite alpha получает `not_measurable`, а не elevated.
5. **Raw vs chronology coordinates:** Stage 2 намеренно использует raw object-normalized + pairwise Kabsch; chronology-aligned массивы не подмешиваются молча.
6. **Date conflict не пройдёт в Stage 3 молча:** текущая перезапись downgrade приводит к final validation error. Это всё равно баг, но fail-closed, а не silent false evidence.
