# Контракты данных

## Входной файл

Поддерживаются JPG/JPEG/PNG, валидное имя `YYYY_MM_DD[_N]`. Декодирование: Pillow EXIF transpose → RGB → OpenCV BGR. Неориентированные байты остаются источником SHA-256.

## Stage 1

Критические массивы `reconstruction.npz`: `ldm106_object_normalized (106,3)`, `ldm134_object_normalized (134,3)`, visibility masks, angles `[pitch,yaw,roll]`, alpha coefficients, identity-only arrays. Все numeric arrays finite; несовпадение shapes — hard fail.

Основной индекс `main_timeline.csv`: photo ID, date, sequence, pose bin, angles, source path, date provenance status и quality fields. `main_index.csv` — compatibility alias.

## Stage 2 Record

`Record.ldm106/ldm134` после патча всегда означают primary analysis coordinates = raw object-normalized. Поле `analysis_space` обязательно публикует это явно. Запрещена тихая подстановка иного пространства.

## Pair row

Обязательные поля: pair ID/type, фото/даты, pose bin, three axis gaps, common visibility, calibrated point count, primary metrics, applicability/exclusion reason, quality/expression flags, calibration coverage, FDR p/q, evidence state. NaN сериализуется по единой policy, а не как строка.

## Версионирование

Любое изменение определения координат, порога, masks, schema field или report interpretation повышает schema/config version. Старые и новые rows нельзя объединять без explicit migration.

## Ошибки API — семантика статусов (ER-166)

Единое правило для всех `/api/v1/*` эндпоинтов. Семантика определяется по категории
ошибки, а не по конкретному эндпоинту; контракт-тесты (`app6/api/tests`) фиксируют
применение на представительных маршрутах.

| Status | Значение | Когда возвращается | Примеры |
|---|---|---|---|
| `400` | Неверный/неподдерживаемый запрос клиента | клиент запросил несуществующий дискриминатор ресурса, недопустимое значение параметра, неизвестное имя артефакта/секции, неверный формат | неизвестный `kind` изображения; артефакт не в allowlist; неподдерживаемые count/space ландмарков; неизвестный job kind; пустой файл; limit/offset вне диапазона |
| `404` | Ресурс не существует в настроенных данных | валидно сформированный идентификатор отсутствует среди сохранённых данных | photo_id нет в Stage 1; пара отсутствует в Stage 2; файл артефакта/секции не создан прогоном; неизвестный job_id |
| `409` | Конфликт с текущим состоянием | зависимость/предусловие не выполнено, либо операция конфликтует с состоянием ресурса | Stage 1/2/3/calibration не настроен; job уже в терминальном статусе; clear-target — симлинк/выходит за storage root |
| `413` | Слишком большой запрос | превышен лимит тела загрузки | загрузка > `DEEPUTIN_MAX_UPLOAD_MB` |
| `422` | Семантически валиден, но не обрабатывается | корректный идентификатор, но содержимое данных повреждено/непроходимо | битый artifact JSON; некорректный landmark CSV; не-finite identity-параметры; невалидная review-структура |
| `500` | Внутренняя ошибка сервера | непредвиденный сбой | неожиданное исключение в обработчике |
| `501` | Метод не реализован в окружении | функция требует недоступную Stage 1-модель | `/api/v1/compare/upload` без весов 3DDFA |
| `503` | Временная недоступность зависимости | необходимая внешняя зависимость недоступна на момент запроса | BFM-геометрия `face_model.tar.gz` отсутствует |
| `507` | Недостаточно места в хранилище | нет места для загрузки | полный диск под `DEEPUTIN_UPLOADS_ROOT` |

Разграничение `400` vs `404`: если клиент запросил идентификатор/дискриминатор,
которого нет в известном перечне → `400`; если идентификатор валиден, но данные
для него отсутствуют → `404`. Это же правило делает независимую валидацию
(например путь парного артефакта) предсказуемой для UI.
