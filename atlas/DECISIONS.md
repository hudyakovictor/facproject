# Принятые решения · 2026-10-19

1. **Первый срез — реальная 3DDFA_V3.** Официальный MobileNet-V3 вместо ResNet-50: два CPU и около 2 ГБ RAM. Это именно V3, не замена на V2. Код upstream: `e15385837dc1e051a6cf376b3827f2e279537b29`. Веса HF закреплены на `ffedf42ca91a072beaaf3bc858fcd752ab3b1502`; SHA-256 в `reports/assets-manifest.json`.
2. **MediaPipe CPU is implemented** for 478 facial landmarks + 10 iris points, with source model SHA-pinned. FAN/AdaFace remain deferred. Eye ratios are descriptive, require quality review, and never assert person identity or mask/authenticity.
3. **Без CUDA, NVDiffrast и TensorFlow.** Официальный Cython CPU-рендерер успешно собран под Python 3.13. Для детекции выбран лёгкий OpenCV YuNet, для пяти точек сохранено POS-выравнивание по стандартному ассету upstream. При нескольких лицах выбирается крупнейшее. Невыявленное лицо — ошибка кадра; готовый выровненный кроп включается только явно.
4. **Канонические меши вместо сравнения повёрнутых голов.** Сохраняем геометрию до вращения и трансляции. Все вершины имеют общую топологию; начало координат и масштаб IOD₀ берутся один раз из среднего шаблона. Это нормированные единицы, не миллиметры. Ручные углы выбирают профиль метрик, но не переформовывают меш.
5. **Тепловая карта — приоритет.** Расстояние по вершинам, только ID, модуль смещения по нормали; пороги, P50–P100, гамма, инверсия, палитры и три собственные цветовые остановки, прозрачности, пороговая маска, сглаживание и гистограмма. Это различие реконструкций, а не доказательство физических изменений или личности. Освещение и качество фото могут влиять на восстановленную форму.
6. **Морфинг 3DMM.** Линейная интерполяция соответствующих канонических вершин эквивалентна интерполяции ID/exp в линейном базисе. Альбедо — оценка 3DMM, не извлечённая фототекстура. Камера экспорта фиксирована. 2–10 фото; пользователь может менять маршрут. Измерения существуют только на исходных фото; промежуточные значения помечены как синтетическая интерполяция.
7. **Пять ракурсов.** Фронт, два полупрофиля и два профиля. Сторона — направление носа на изображении; positive yaw → вправо. Каждый профиль проверяет yaw/pitch/roll. При пересечении действует порядок в YAML, интерфейс предупреждает. Вне диапазонов — `unclassified`, а не принудительно ближайший профиль.
8. **Три честные стартовые метрики 3DDFA.** Площадь глазной щели / IOD²; ширина между точками 4/12 относительно 0/16 контура ldm68; проекция носа / IOD. Не называем эти контурные точки точными антропометрическими bigonial/bizygomatic. `metrics.txt` не предоставлен, поэтому base17 и неизвестные формулы не выдуманы. σ параметров ID без валидированного эталонного распределения не заявляем.
9. **Робастный z — внутри группы и ракурса.** Формула `(x−median)/(1.4826·MAD)`; менее трёх значений или нулевой MAD не порождают фиктивную оценку. Пороги хранятся в паре модель×ракурс и подсвечивают выбросы на исходных точках.
10. **One infinite canvas; two principal panels.** Based on the explicit usability correction, scene/morph/photos share one node, and synchronized dated metrics share a separate node. Side nodes remain optional: source, 3DDFA processor, eyes, α_id cluster. Nodes have explicit dock navigation and grab/pan keyboard shortcuts; removing nodes does not delete photo files.
11. **Много метрик.** Автообнаружение файлов Python, декларативные YAML, поиск и выбор дорожек. Дорожки виртуализированы; область графиков меняет высоту и прокручивается независимо. Новая метрика при стандартном выборе автоматически появляется на таймлайне.
12. **Кэш по зависимостям.** Признаки зависят от SHA файла, версии модели/весов, кропа и порога детектора. Метрики — от конкретной функции, её общего кода, конфигурации и ракурса. Проекция — от набора признаков и параметров. Визуальные пороги не запускают инференс. Версия признаков входит и в браузерный ключ меша.
13. **Synthetic demos are explicitly opt-in and removable.** They may be moved to the recycle bin, restored, or purged permanently after user confirmation. The purge API can operate only on photos explicitly tagged `demo=true`. When real photos exist, app startup chooses a non-demo group instead of `__all` or demo-only groups. No demo/bootstrap inference runs on startup.
14. **Производственный preview из FastAPI.** Собранный Vite обслуживается тем же origin, что API и SSE; браузер не обращается к localhost. Один процесс модели и последовательная очередь. В разработке Vite использует `/api` proxy. Для маленькой RAM esbuild ограничен через GOMEMLIMIT/GOGC.
15. **Крупные веса — в исключённом `.cache`.** Arena не сохраняет зависимости, `.cache` и `dist` в снимках и ограничивает объём снимка. Поэтому не пытаемся незаметно упаковать 117 МБ весов вместе с данными пользователя. `scripts/setup.sh` и `scripts/start.sh` восстанавливают окружение/ассеты. Кэш результатов и исходный код находятся в обычных сохраняемых каталогах.
16. **За рамками первого этапа.** Drive API/rclone, AdaFace-облако, FAN/AdaFace, their cross-model alignment, CPU-export phototexture, 2D Delaunay-morphing, CUSUM/PELT и полная история версий интерфейса. Текущий рабочий экспорт — 3D MP4; детектор скачков — MAD-порог. Ничего из перечисленного не изображается работающим.


## Финальный CPU/production-путь

- Один процесс FastAPI обслуживает API и `web/dist` на 5173, экономя память 2 GB среды. Vite оставлен для разработки. Веса и зависимости восстанавливаются `scripts/setup.sh`; полный setup повторно поверх текущей среды не запускался, production-start проверен.
- Тепловая статистика вычисляется вне Canvas, поэтому автоматический перцентиль/гистограмма не зависят от WebGL. CPU-preview ограничивает поток PNG (один запрос одновременно), а не debounce, который останавливал промежуточные кадры при Play. Ключ запроса включает только параметры PNG: переключатели SVG-точек не блокируют следующий кадр.
- Без WebGL CPU-рендер поддерживает основные параметры карты, мышь yaw/pitch, масштаб, реальные 68/106/134 точки и индекс. SVG-точки синхронизируются с реально загруженным PNG. Разреженная сетка и ориентировочное отсечение точек нормалью — явно принятые ограничения fallback.
- Без WebGL трёхмерные координаты облака остаются настоящими, но выводятся как отмеченная проекция XY; отсутствие GPU не приводит к падению всего canvas.
- Для MP4 сохранённой топологии достаточно: нейросеть не загружается заново ради треугольников. Отдельный эталон включён в JSON-происхождение с хэшем и метаданными.
- 37 backend, 21 production UI и 15 job-проверок прошли. В том числе настоящий UMAP на 10 реконструкциях, 3D t-SNE/PCA, отмена длинного экспорта и декодирование трёх rich MP4. Пользовательские рабочие файлы в тестах не сбрасываются.


## UX rework and ocular morphometry · 2026-10-19

- Respect the user correction: `scene` and `timeline` are separate, adjacent central nodes. The scene node contains only the 3D/head/heat/original photo source, thumbnails, morph controls/export. The metric timeline has its own dated axis and tracks. Resizeable/drag-handle headings, dock shortcuts, toggleable minimap, whole-canvas hand mode and wheel-pan improve navigation. Workspace v1/v2 layout is migrated to compact v3 while preserving user files and measurements.
- Default view excludes synthetic demo photos if real user photos exist. They can be restored from trash or purged only via explicit confirmation; purge code rejects any non-demo photo id and never removes users' assets.
- Original-resolution, EXIF-corrected input texture is perspective projected onto canonical 3DDFA mesh through per-vertex source coordinates, cached by model/reconstruction key. This uses original pixels, not 3DDFA PCA albedo. Geometry remains 35,709 vertices; UV seams/occlusion are approximate. This rendering feature needs WebGL; CPU fallback still renders geometry and heat without native photo color.
- MediaPipe 0.10.35 CPU FaceLandmarker is installed from the official Face Landmarker task (Apache-2.0), pinned and SHA checked by `scripts/download_mediapipe.py`. Native-pixel landmarks plus explicit manual edits, gaze/head corrections, quality score and review checkbox persisted separately. Twenty descriptive relative measures are delivered to the eye node, CSV and registry, not a mask detector.
- Automatic comparison never names/identifies an individual or asserts mask presence. Eye aperture / iris, nose/bridge and face/soft-jaw ratios remain observational, not biometric authentication. Local user data has five unsorted face views in **one** group; all five were excluded from strict frontal sample (yaw about -29°…-32°, pitch +11°…+14°). No three cohorts, Google Drive `groups` folder or angle table was found in the connected Drive search. Until the user supplies the precise folder/table and groups, do not import unrelated dated Drive images or infer identity classes.
- Current backend cache keys include ocular model/detection/manual revisions. Editing landmarks invalidates dependent eye metric outputs without re-running 3DDFA.

## UV atlas correction and noise calibration (2026-10-20)
- Replaced the live preview's image-space per-vertex UV override with a cached canonical-template UV atlas. The baker uses the repository's core idea: triangle-wise affine UV→source-image sampling, overlap accumulation, source bounds checks, and the original 3DDFA topology/UVs. Source pixels are baked into a PNG atlas (`/api/photos/{id}/uv-texture`) on demand. The beauty/inpaint texture is intentionally not used for quantitative comparison; only a tiny raster crack fill is applied. Out-of-frame model projections remain out-of-range (not clamped to image edges) to avoid edge smearing.
- Added a seven-participant calibration panel in heat-map settings. User assigns 2–3 ready, non-demo photos to each participant. Backend computes per-vertex displacement from that participant's own median mesh, then takes the 75th percentile across participants. This avoids treating between-person face shape as noise. Optional correction subtracts this threshold from geometric distance heat values (floor zero); it does not alter identity/normal metrics. Calibration is saved under `cache/calibration/noise-v1.json` and can be rebuilt with new selections.
- Calibration is a repeatability baseline, not a claim of pure model error: expression, image quality, pose-conditioned fitting, and actual within-person variation may contribute. Compare matched pose/expression/quality where possible, and retain raw heat-map mode.
- Source implementation reviewed: `uv_module/uv_baker.py`, `uv_module/hd_uv_generator.py`, and `UV_MODULE_TZ.md` in https://github.com/hudyakovictor/facproject/tree/main/uv_module. Adapted the algorithmic approach, not the entire dependency-heavy module.
- Verification: TypeScript/Vite production build passes; two isolated unit tests for UV baking and calibration pass. Full backend suite: 36 pass, 3 fail because this restored snapshot lacks excluded 3DDFA model assets (not code failures established); therefore live photo texture baking/3DDFA-dependent end-to-end rendering remains unverified until assets are restored. No user's photo was processed during tests.

## Photo-on-mesh usability correction (2026-10-20)
Browser inspection with restored model assets found the real usability defect: the `Фото`/UV button's active indicator was wired to the albedo texture flag instead of `photoTexture`, while the viewer did load the baked UV atlas. This made the photo control look disabled despite a successful texture. Fixed the binding, renamed it `Фото UV`, added loading/ready/error status, and softened heatmap vertex tint over the photo so source detail remains recognizable. Verified in Chromium: UV status reports loaded, photo button active, 3D preview displays the source image on the mesh, and there were no console errors. The server-side asset restoration and processing job already completed for seven non-demo photos (zero errors); user data retained. Removed local debug screenshots after inspection.
- Follow-up: made the viewport modes mutually explicit (`Карта`, `Фото UV`, `Фото + Δ`, `Сетка`), so a user can isolate the source texture from the heat layer. Added retry while UV bake is not ready and a persistent `UV · загружена/загрузка/ошибка` badge. The previous texture control's active-state indicator had read the wrong setting; corrected. Chromium check after the fix confirmed atlas loads, all three viewing modes switch, and no browser console/page errors.
