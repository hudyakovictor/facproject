# UI v5 — экспертная оценка всех 23 дизайн-рендеров по 19 факторам

**Дата:** 2026-08-05  
**Предмет оценки:** только дизайн-концепции из `ui-v5/screens`, а не готовность локального runtime.  
**Важно:** принято уточнение владельца проекта — веса моделей существуют в локальной версии и не передавались из-за размера. Их отсутствие в checkout **не снижает оценки рендеров**.

> Оценки характеризуют пригодность экранов для исследовательской forensic workstation по текущему ТЗ. Они не оценивают и не подтверждают гипотезу о личности изображённых людей.

---

## 1. Методика

Каждый фактор оценивается по шкале 0–100. Итог — взвешенная оценка. Если фактор объективно не относится к специализированной странице, стоит `—`, и итог нормируется по оставшимся весам. Поэтому сравнивать лучше:

- таймлайны с таймлайнами;
- pair workspaces с pair workspaces;
- clustering с clustering;
- служебные страницы со служебными страницами.

## 6. Подробный разбор каждого рендера

## R01 — Timeline live filters — 83.1

**Сильные стороны**

- верхние раскрывающиеся меню вместо постоянных sidebar;
- один активный ракурс;
- фильтры и пороги меняются прямо над таймлайном;
- годы находятся внизу, фото привязаны к общей оси;
- хорошо показаны скрытые периоды и число скрытых кадров.

**Проблемы**

- две открытые панели одновременно закрывают центральный участок данных;
- metric lanes представлены в основном цветными точками без ясной шкалы;
- фотографии слишком малы относительно пустого верхнего пространства;
- A/B workflow почти не раскрыт;
- в оси заметна потенциально ошибочная/дублирующая подпись года;
- красный/зелёный используются без достаточного дублирования формой.

**Вердикт:** сохранить паттерн live dropdown, но перестроить сами metric lanes.

## R02 — Nine-pose coverage — 81.7

**Сильные стороны**

- все 9 bins показаны одновременно и в каноническом порядке;
- видны count, median quality, yaw distribution и coverage matrix;
- сразу выявляются пробелы в ракурсах/эпохах;
- экран реалистично связывается с calibration/dataset inventory.

**Проблемы**

- название «Профили» конфликтует с analysis profiles/selection profiles;
- девять почти одинаковых крупных карточек создают повторяемость;
- один slider MAD в каждой карточке визуально выглядит как независимый scientific threshold;
- не объясняется difference между coverage, confidence и calibration readiness;
- representative portraits занимают много места, не добавляя столько же информации.

**Вердикт:** переименовать в «Покрытие ракурсов»; сделать экран компактнее на 20–25%.

## R03 — Data Manager / provenance — 84.1

**Сильные стороны**

- наиболее реалистичный data-oriented рендер;
- filename date, sidecar, SHA, conflicts и near-duplicates видны без JSON dump;
- правильная master-detail компоновка;
- импорт/проверка provenance/пересчёт находятся рядом;
- pagination и фильтры пригодны для большого архива.

**Проблемы**

- правый inspector слишком широк, если открыт постоянно;
- нет dependency preview перед destructive/recompute actions;
- не показана полноценная очередь ingest/extract с progress/ETA;
- image preview должен отличать source image от face crop;
- provenance status лучше кодировать иконкой + текстом, не только цветом.

**Вердикт:** хорошая основа служебной страницы; sidebar здесь допустим как временный drawer.

## R04 — Focus timeline v2 — 89.9

**Сильные стороны**

- лучше всего соблюдён инвариант «одно фото = одна вертикаль данных»;
- фото расположены ниже центра, графики сверху, markers снизу, годы внизу;
- A/B, pair bracket, interval brackets, density и pose coverage находятся на одной оси;
- нет постоянных боковых панелей;
- фото остаются главным визуальным объектом;
- хороший баланс между forensic density и человеческой читаемостью.

**Проблемы**

- крупные карточки позволяют показать только 8–10 кадров на viewport;
- шесть рядов кружков выглядят как status matrix, но не как тенденции;
- короткие labels `кач/conf/bone/орб/скул/сим` требуют tooltip/легенду;
- не показана стратегия zoom-dependent aggregation для ~1900 кадров;
- calibration/uncertainty почти не видны.

**Вердикт:** одна из трёх главных основ будущего таймлайна.

## R05 — Timeline findings — 85.7

**Сильные стороны**

- наиболее сильная anomaly-first композиция;
- хорошо различены point event, interval, return и pair relation;
- findings dropdown показывает реестр и review state;
- A/B связь остаётся видна в хронологии;
- полный период 1999–2024 не теряется.

**Проблемы**

- почти все невыбранные фото чрезмерно затемнены и теряют функцию контекста;
- красный доминирует и может визуально превратить candidate в verdict;
- правый WHAT-IF блок фактически становится постоянным sidebar;
- не показаны quality/provenance причины, способные объяснить находку;
- надписи периодов конкурируют с markers.

**Вердикт:** использовать как переключаемый режим «Находки», не как default timeline.

## R06 — Landmark A/B v1 — 82.6

**Сильные стороны**

- крупное сравнение лиц и landmark vectors;
- RMS, p95, calibration thresholds и зоны расположены логично;
- A/B различаются цветом;
- переход к chronological pair strip уже намечен.

**Проблемы**

- нет большого thumbnail browser и range selection;
- слишком много мелкого текста;
- мало provenance/quality/applicability;
- right metrics panel перегружен и неясно, является ли он live drawer;
- зоны показаны цветными барами, но excluded/visible zone semantics недостаточны.

**Вердикт:** полезный ранний вариант, полностью перекрывается R19.

## R07 — Сверхплотный forensic timeline — 81.5

**Сильные стороны**

- действительно раскрывает в несколько раз больше данных;
- охватывает metrics, quality, landmarks, texture, events, eras, heatmap и navigator;
- anomaly callout хорошо связывает несколько confounders;
- один ракурс и единая временная ось сохранены.

**Проблемы**

- критически мелкий текст;
- слишком много одновременно активных линий;
- визуальная иерархия почти исчезает;
- на реальном 4K/Retina экран может быть полезен, но на обычном мониторе нечитабелен;
- accessibility низкая;
- эксперт не сможет быстро отличить основной сигнал от диагностического.

**Вердикт:** использовать как источник функциональных слоёв, но не как основу дизайна.

## R08 — Timeline: события и связи — 83.2

**Сильные стороны**

- почти идеальная вертикальная привязка фото, точек и markers;
- хорошо видны return, texture, pair и change-point;
- эпохи и navigator остаются внизу;
- аномальные периоды читаются быстро.

**Проблемы**

- плотность точек и линий снова выше безопасного уровня;
- фото слишком малы;
- некоторые symbols не имеют самодостаточной легенды;
- много сигналов строятся одним цветом и требуют shape encoding;
- не хватает contextual tooltip/inspector state.

**Вердикт:** хороший слой markers для объединения с R23/R04.

## R09 — Landmark A/B, альтернативный рендер — 79.1

**Сильные стороны**

- понятная базовая структура пары;
- крупные faces и vectors;
- присутствуют threshold bands и зоны.

**Проблемы**

- визуально менее чистый и менее полный, чем R06/R11/R19;
- верхняя служебная строка генерации не должна попадать в дизайн-референс;
- нет развитой chronological selection;
- микротипографика и cramped layout;
- мало нового относительно дубликатов.

**Вердикт:** не использовать как базовый референс.

## R10 — Morphing chronology v1 — 83.5

**Сильные стороны**

- понятная последовательность по годам;
- 3D-модель — главный объект;
- heatmap, wireframe, auto-rotation и blend представлены явно;
- scrub timeline находится прямо под моделью;
- visualization-only boundary видна.

**Проблемы**

- постоянные панели слева и справа отнимают площадь;
- player controls всё ещё заметнее ручного range workflow;
- не показан полноценный zoom выбранного диапазона;
- мало layer combinations: texture/model/heat/landmarks/zones;
- fixed sequence из 12 кадров не раскрывает стратегию для сотен фото.

**Вердикт:** сохранить chronology sequence, но перенести controls в overlay по модели R20.

## R11 — Landmark A/B v2 — 88.7

**Сильные стороны**

- сильный A/B canvas;
- LDM106/134, vectors, numbers и zones управляются live;
- есть range brush и chronological strip;
- допустимый/подозрительный пороги визуально связаны с результатом;
- понятен переход «к morphing».

**Проблемы**

- одна строка миниатюр хуже requested 4-row browser;
- отсутствует similarity tint всех thumbnails относительно A;
- нет раннего reference period comparison;
- right panel нужно делать collapsible overlay;
- calibration/diagnostic threshold distinction должен быть заметнее.

**Вердикт:** почти production-ready layout; объединить с R18 и R19.

## R12 — Clustering chronology — 84.5

**Сильные стороны**

- полностью соответствует требованию раскладывать clusters по хронологии;
- transitions видны как связи между cluster lanes;
- есть pose/feature/algorithm controls;
- параметры HDBSCAN и sensitivity находятся рядом с графиком;
- нижняя матрица эпох помогает видеть смены состава.

**Проблемы**

- без backend artifact числа выглядят убедительнее, чем обоснованы;
- cluster IDs могут ошибочно восприниматься как личности;
- линии между точками создают впечатление последовательной траектории там, где это membership;
- нужны bootstrap stability, outlier status и sensitivity bands;

## 9. Итоговый экспертный вывод

Рендеры уже формируют сильный визуальный язык профессиональной forensic workstation. Главная проблема не в отсутствии хороших идей, а в том, что лучшие решения распределены по разным вариантам.

**Не следует выбирать один PNG и буквально его копировать.** Оптимальный UI v5 должен быть собран как система из лучших частей:

- R23 + R04 + R21 + R05 для timeline;
- R19 + R18 + R11 для pair analysis;
- R20 + R10 для morphing;
- R15 + R12 + R13 для clustering;
- R16 + R17 для private hypothesis validation.

Три дизайна, которые не стоит брать как основной фундамент:

1. **R07** — слишком высокая плотность и микротипографика;
2. **R14** — декоративная cloud geometry снижает forensic точность;
3. **R09** — слабее и менее полный дубликат pair workspace.

Лучший одиночный экран: **R19 — 92.2/100**.  
Лучший основной timeline shell: **R23 — 90.7/100**.  
Лучший live-control pattern: **R21 — 90.8/100**.  
Лучший morphing: **R20 — 91.3/100**.  
Лучший clustering: **R15 — 86.7/100**.
