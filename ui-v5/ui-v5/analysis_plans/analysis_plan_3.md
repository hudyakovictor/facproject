# План анализа и исправления UI v5 (анализ 3/50)

## Анализ 3: LLM-ландмарки и API-доступ к геометрии

### Проблема P2: Landmark data недоступно через API
- `server.py:258-280` эндпоинт `/api/v1/photos/{photo_id}/landmarks/{count}/{space}` возвращает 404
- `_LANDMARK_FILES` ссылается на CSV файлы (`ldm106_raw.csv`, `ldm106_chronology.csv`), которых нет в Stage 2 данных
- Реальные данные landmarks хранятся в `pair_details.json` с ключами `ldm106_anchor_count`, `visibility_gate_accepted106` и т.д.

### Решение:
1. Переписать `get_photo_landmarks()` для чтения из `pair_details.json` или соответствующего источника
2. Добавить fallback к существующим CSV файлам при их наличии
3. Добавить обработку случая когда landmark data недоступен (возвращать null вместо ошибки)

### Проверка:
- `/api/v1/photos/1998_01_01__9714228198ba/landmarks/106/raw` возвращает данные
- Формат ответа совпадает с ожиданиями UI (points: [[x,y,z], ...])

### Приоритет: P2 (нестабильная визуализация)

### Шаги:
1. Изучить структуру pair_details.json для понимания формата landmark data
2. Обновить server.py для чтения landmark data из правильного источника

4. Обновить UI-компоненты для обработки null-ответов
