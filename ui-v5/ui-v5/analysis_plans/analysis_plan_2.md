# План анализа и исправления UI v5 (анализ 2/50)

## Анализ 2: Zod схемы и API-контракты

### Проблема P1: Zod `.catch()` скрывает contract errors
- `shared/api/schemas.ts:115+` превращает неверные ответы в null/default вместо блокирующей schema error
- Это делает невозможным обнаружение и исправление нарушений contract на клиенте

### Решение:
1. Убрать `.catch()` из Zod схем
2. Добавить валидацию на сервере (pydantic)
3. Сделать ошибки 400/422 вместо null

### Проверка:
- Найти все Zod схемы в `shared/api/schemas.ts`
- Проверить, где используется `.catch()`
- Убедиться, что сервер возвращает валидные ошибки

### Приоритет: P1 (сломанный контракт)

### Шаги:
1. Прочитать `shared/api/schemas.ts` и найти все `.catch()` в Zod
2. Проверить серверные эндпоинты на валидную валидацию

### Критерии завершения:
- Все Zod схемы работают без `.catch()`
