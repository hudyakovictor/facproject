# План анализа и исправления UI v5 (анализ 5/50)

## Анализ 5: Zod схемы и contract errors

### Проблема P1: Zod `.catch()` скрывает contract errors
- `shared/api/schemas.ts:115+` превращает неверные ответы в null/default вместо блокирующей schema error
- Это делает невозможным обнаружение нарушений contract на клиенте

### Решение:
1. Найти все Zod схемы в `shared/api/schemas.ts`
2. Убрать `.catch()` из схем
3. Добавить валидацию на сервере (pydantic) для возврата 400/422 ошибок
4. Обновить UI-компоненты для обработки валидационных ошибок

### Проверка:
- Zod схемы не используют `.catch()`
- Невалидные ответы сервера возвращают 400/422 вместо null
- UI показывает ошибки валидации пользователю

### Приоритет: P1 (contract issues не блокируют query)

### Шаги:
1. Прочитать `shared/api/schemas.ts` и найти все `.catch()` в Zod
2. Убрать `.catch()` и обеспечитьPropagation ошибок
3. Проверить серверные эндпоинты на валидную валидацию
4. Написать тесты, проверяющие валидные/невалидные ответы

### Критерии завершения:
- Все Zod схемы работают без `.catch()`
- Сервер возвращает 400/422 при нарушении contract
- Тесты проходят для валидных и невалидных данных
