# Validation

Эта папка — отдельный слой валидации пайплайна `app6`.

Её задача — не дублировать Stage 1 / Stage 2 / Stage 2B / Stage 3, а проверять,
что результаты каждого этапа можно считать достоверными в пределах текущей версии.


## Подход

Проверка идёт **последовательно**: от самых общих инвариантов к более локальным.

Сначала проверяется не смысл аномалий, а право вообще доверять набору артефактов:
- существует ли ожидаемый набор файлов;
- совпадает ли версия схемы;
- нет ли структурных дыр;
- можно ли однозначно связать сущности между файлами.

Только после этого имеет смысл переходить к:
- законности формирования пар;
- согласованности мимики и позы;
- качеству калибровки;
- первичным метрикам;
- FDR;
- хронологии;
- evidence;
- Stage 2B;
- Stage 3.


## Почему так

Сильный вывод на позднем этапе может оказаться недостоверным из-за маленькой ошибки
на раннем этапе. Поэтому логика здесь обратная обычному exploratory analysis:
сначала строится цепочка доверия, и только потом разбираются интересные пары.


## Принципы CLI-скриптов

Каждый скрипт:
- решает **одну** проверочную задачу;
- читает только нужные ему файлы;
- печатает только `ERROR`, `WARN` и компактный `SUMMARY`;
- не выводит бесконечные `OK`-логи;
- рассчитан на пересылку результата в чат как обычного терминального вывода.

Формат сообщений:

```text
ERROR code=... subject=... detail=...
WARN  code=... subject=... detail=...
SUMMARY script=... checked=... errors=... warnings=...
```

## Первая проверка

`check_stage2_contract.py` — базовый структурный аудит директории Stage 2.

Он отвечает на вопрос:

> Можно ли вообще считать, что текущий Stage 2 output структурно целостен и
> пригоден для следующих проверок?

Этот тест не проверяет научную достоверность метрик.
Он проверяет фундамент:
- наличие ожидаемых файлов;
- читаемость JSON / CSV;
- корректность schema;
- наличие обязательных ключей верхнего уровня;
- отсутствие дублей идентификаторов;
- отсутствие ссылок на несуществующие `photo_id` / `pair_id` там, где это очевидно из артефактов;
- наличие минимальной связности между главными файлами Stage 2.
