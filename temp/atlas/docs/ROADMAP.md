# ATLAS — план доработок интерфейса и системы

Дата: 2026-10-20. Статус: черновик дорожной карты после исправления непрерывности тепловой карты в морфинге.

Приоритеты: **P0** — известные баги и техдолг, влияющие на корректность; **P1** — качество визуализации и ежедневного UX; **P2** — архитектура, производительность, новые возможности.

---

## P0. Исправления и техдолг

### 1. Баг t-SNE при малом числе образцов
- **Симптом:** UI показывал `n_components=3 must be between 1 and min(n_samples, n_features)=2`.
- **Файл:** `server/analysis.py` (~строка 154).
- **План:** перед вызовом t-SNE/PCA ограничивать `n_components = min(requested, n_samples, n_features)` и, если итоговая размерность < требуемой для сцены, возвращать паддинг нулями + флаг `degenerate: true` в ответе, чтобы UI показывал пояснение, а не traceback.

### 2. Размер JS-бандла (~1.47 MB чанк)
- **Файл:** `web/vite.config.ts`.
- **План:** `manualChunks` — отделить `three`/WebGL-графику и тяжёлые библиотеки от ядра; ленивый `import()` для `Viewer`, `SceneNode`, `PhotoEditor`. Цель — initial chunk < 600 KB.

### 3. Насыщение теплокарты при больших смещениях (кейс 2007→2020)
- **Факт:** 41% вершин упираются в vmax; обсуждены варианты: поднять vmax до ~0.115 (p95 маршрута), включить опциональную нормализацию по IOD.
- **План:**
  - в панель Timeline/Viewer добавить кнопку «Подогнать шкалу под маршрут» — единый vmax = перцентиль по ВСЕМ парам маршрута (сохраняет сопоставимость внутри pose-группы, не независимая автонормализация каждого фото!);
  - в легенду рядом со шкалой выводить «% вершин за пределами шкалы» — индикатор клиппинга;
  - экспорт MP4 (`server/rendering.py`) использует тот же вычисленный vmax, что и preview (сейчас fallback 0.06 при отсутствии параметра — заменить на передачу фактического значения из UI).

### 4. Регрессионные тесты на экспорт
- **Файл:** `scripts/acceptance_jobs.py`, `tests/`.
- **План:** автотест, который рендерит короткий MP4 (несколько кадров) и проверяет: полный декод ffmpeg; теплокарта присутствует на первом кадре, если у первого фото маршрута есть хронологический predecessor (сравнение первого кадра с texture-only рендером, порог по средней RGB-разнице); пиксельное совпадение карты на стыке сегментов. Именно эти критерии пользователь предъявлял вручную — зафиксировать их в CI, чтобы баг не вернулся.

## P1. Визуализация и UX

### 5. Индикация качества данных
- **Зачем:** часть «красноты» теплокарты — шум реконструкции (масштаб камеры ±5–6% IOD, мимика, освещение), и пользователь должен видеть это отдельно от реального изменения.
- **План:**
  - per-photo quality score (резкость/лапласиан, yaw/pitch, уверенность фиттинга) — бейдж на миниатюре в Timeline;
  - предупреждение «годится для сравнения / есть риск артефактов» при добавлении фото в маршрут;
  - над шкалой теплокарты — строка декомпозиции: «форма X / общий масштаб Y» (числа уже считаются: `scaleChangePct` в `heat.ts`).

### 6. Переключатель «вычесть глобальный масштаб»
- **Статус:** нормализация по IOD опциональна и выключена по умолчанию (требование пользователя — IOD индивидуален).
- **План:** сделать режим отображения трёхканальным: `сырой` / `форма (без масштаба)` / `только масштаб`. По умолчанию — сырой. Для экспорта — та же настройка, что в preview.

### 7. Улучшение читаемости MP4
- Легенда со шкалой vmin→vmax и цветовой полосой, вшитая в кадр экспорта (сейчас видео без шкалы — «красное» не имеет числового смысла).
- Подпись сравнения в углу: `2007-04-19 → 2020-03-08, reference: 2007`, дата и прогресс маршрута.
- Экспорт PNG-сериалов и GIF в дополнение к MP4; настройки fps/разрешения в UI Timeline.

### 8. Режимы сравнения в Viewer
- Сплит-экран A/B и вертикальный «шторка»-слайдер поверх одного меша (texture / heat обеих сторон).
- Overlay 68-landmarks на фото-режиме для ручной проверки фиттинга.
- Кнопка «кадр назад/вперёд» и прокрутка по кадрам (frame scrubbing) в дополнение к Play.

### 9. Timeline: редактирование маршрута
- Drag-and-drop переупорядочивание фото в маршруте с пересчётом reference-пар.
- Множественный выбор, дублирование маршрута, именованные пресеты (fps, vmax, gamma, режим).
- Предпросмотр reference-пары при наведении на сегмент (мини-панель «A vs ref»).

### 10. SceneNode / DataNodes
- Подсветка выбранных фото маршрута на сцене; цветовая кодировка по pose-группам.
- Фильтры: дата-курсор, качество, кластер.
- Tooltip с метрическими значениями (IOD, eye area, jaw ratio) при наведении на узел.

## P2. Архитектура и новые возможности

### 11. Производительность фронта
- Перенос расчёта теплокарты (`heat.ts`, сглаживание по 50k+ вершин) в Web Worker — сейчас Play может подвисать на слабых машинах.
- Реюз `BufferGeometry` атрибутов вместо пересоздания; прелоад соседних сегментов маршрута во время воспроизведения.

### 12. Надёжность экспорта
- Прогресс-бар джобы в реальном времени (SSE/polling уже есть в `jobs` — вывести тайминги по кадрам), отмена и повтор упавшей джобы.
- Идемпотентная очистка временных UV-файлов (после старого race-condition фикса — добавить тест).

### 13. Метрики и аналитика
- Панель «Морфометрия»: таблица попарных метрик по маршруту (среднее смещение, p95, scaleChangePct, региональные разбивки: лоб/глаза/нос/челюсть) с экспортом CSV.
- Региональная агрегация теплокарты — средний |Δ| по анатомическим зонам, чтобы «сильная карта» переводилась в числа; база кода уже есть (`metrics/`).

### 14. Данные
- Версионирование `library.json`/`groups` (backups при записи), защита кэша — по требованию «не портить uploads/cache/user records».
- Мультизагрузка с автогруппировкой по дате из EXIF/имени файла.
- Опционально: усреднение нескольких фото одной даты для снижения шума реконструкции.

### 15. Тестовое покрытие UI-критических путей
- Playwright-сценарии: загрузка фото → построение маршрута → Play (нет «чернения» лица) → экспорт → MP4 содержит карту на первом кадре. Связать с P0.4.
