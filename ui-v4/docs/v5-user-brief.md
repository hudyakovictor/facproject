Собрано из полной истории диалога. Разделено на: **прямые требования пользователя** и (в приложении) факты проекта, собранные из кода/документов. Дата сборки: 2026-08-05.

## 1. Цель и процесс

- Редизайн UI проекта (текущий — `ui-v4/`, кодовое имя **DEEPUTIN V5**) через сгенерированные дизайн-макеты; **только после утверждения дизайна** — сборка реального ui-v5.
- Ключевая установка (дословно): «важно понимать что ты должен в будущем собрать все без абстрактных визуализаций. некоторые участки кода (которые не касаются дизайна и визуализаций ты можешь перенести оттуда)».
  → Никаких абстрактных визуализаций: каждый экран маппится **1:1 на реальные данные ui-v4 и API**; не-дизайновый код (api-клиент, типы, рендереры, логгер) **переносится в ui-v5 как есть**.
- Общение на русском.

## 2. Дизайн-язык (зафиксирован)

- Фон `#0b0e13`, панели `#10141b`, бордеры 1px `#2b323e`.
- Акценты: cyan `#68c3cf`, amber `#efb84d`, red `#f26b5e`, green `#66bd82`, purple `#b585e7`, teal `#62ced5`.
- Типографика Inter; метки читаемые **12–13px+**; данные — mono.
- Футер всегда: **`ОТОБРАЖЕНИЕ ДАННЫХ · НЕ ВЕРДИКТ`**.
- **Без избыточных glow/неоновых/bloom-эффектов** — плоско, матово (явное требование при таймлайн-состояниях).

## 3. Доктрина раскладки (строго)

- **Никаких левых/правых сайдбаров.** Все меню — в **одном компактном топбаре** как dropdown-блоки:
  `РАКУРС ▾ · МЕТРИКИ 6/24 ▾ · ФИЛЬТРЫ ▾ · НАХОДКИ ⚑ ▾ · СРАВНЕНИЕ ▾ · ВИД ▾`
  + чипы статусов: зелёный `STAGE 1 ✓`, cyan `FDR 0.05`, серый `BLIND: OFF`, `⌘K`, аватар.
- Таймлайн занимает весь экран.

## 4. Доктрина таймлайна (строго, все правила пользователя)

1. Развёрнут **только один ракурс** (один pose) за раз.
2. **Один ряд фото**, расположен **чуть ниже вертикальной середины**.
3. **Графики ВЫШЕ** фото-ряда; **иконки/маркеры НИЖЕ**; **линейка годов ВНИЗУ**.
4. Каждое фото = **ровно одна колонка данных**: все точки графиков и маркеры защёлкнуты на x позиции фото.
5. Парные метрики — **между колонками** (браслеты).
6. Временные спаны (эпохи, persistent change) = полупрозрачные области.
7. **Аномалии / изменения формы / текстуры — высший визуальный приоритет.**
8. Почти **ноль горизонтального текста** внутри прокручиваемой зоны: таймлайн скроллится влево/вправо и зумится колесом; только мелкие иконки; весь текст — в hover-тултипах.
9. Калибровка порогов таймлайна — **плавающая live-панель над таймлайном**, мгновенное применение.

## 5. Парадигма настроек (строго)

- Контекстные панели живут **там, где действуют**: градиент-слайдеры морфинга — на странице морфинга; пороги таймлайна — плавающая панель над таймлайном; пороги лендмарок — в виджете лендмарок. Обновление мгновенное (live).
- Внутренняя страница «Настройки» — **только глобальные дефолты + загрузка тестового фото**.

## 6. Требования по разделам

### Морфинг
- **Не видео-плеер**: ручной скраб — основной сценарий (крошечная play-кнопка в углу), scrubber на всю ширину.
- **Re-scope диапазона**: 1999–2026 → увеличить до 2009–2012 и т.п. через overview-миникарту с ⚑ флагами.
- Панель «больше параметров»; слои-чекбоксы (текстура / тепло / точки 106).

### Photo Lab
- Фото + большая 3D-сцена; **чипы режимов ВНУТРИ вьюпорта**: `3D / UV / 3D+текстура / точки 106 / точки 134 / зоны / маска`.
- Компактное облако data-чипов из info.json/texture.json — **никаких больших таблиц**.
- Свёрнутые строки `▸ info.json`.

### Сравнение лендмарок
- A/B с **двухрычажным скрабером пары** (выбор диапазона-пары).

### Парный анализ
- Сетка превью 4 ряда по 40px с зелёным/красным оверлеем ±20% похожести; референс-период 1999–2005 («A ближе на 38%»).

### Кластеры (диагностика, Stage 1 не трогаем)
- Экраны: хронология (swimlanes + braid переходов + эпохи), UMAP-embedding (инспектор, membership ≥ 0.50, ghost-точки), облако far/near (зум 0.8 «туманности» / 2.6 упакованные превью), переключения (band назначения хронологии, boundary detection PELT, консенсус 9/9 по бинам, реестр B1–B4).

### Валидация гипотез (бывш. «карантин» — переименовано по требованию)
- **Не называть «карантин»**: страница = «Тестирование гипотез» / **«Валидация гипотез»**.
- **Данные этого раздела НЕ попадают в общие результаты** (и отчёты/Stage 1/2/3) — изолированный контур.
- В основе — **3 сущности: PUTIN, UDMURT, VASILICH**; в гипотезах собрано много данных об их отличиях:
  1) чем отличается **первый от двух других** и по каким признакам его выявить;
  2) чем отличаются **2 и 3 друг от друга**;
  3) как отличаются **1 и 2** и **1 и 3**.
- **Три крупных блока с плитками описаний гипотез**, фильтр по ракурсу, **обязательно панели калибровки порогов**.
- Результаты основного датасета накладываются на гипотезы: плитки получают **слегка красный / слегка зелёный оверлей + % совпадения** полученных данных с ранее собранными гипотезами.
- Охватить **90+ гипотез**, полученных ранее.
- **Важнейшее уточнение**: все ранние значения гипотез получены **по не до конца выровненным ключевым точкам** → вероятно **все данные имеют систематическое смещение** → в разделе нужно **значительно больше параметров калибровки**: сдвигать пороги в обе стороны, **расширять и сужать диапазоны**, иметь **все инструменты проверки и изменения всех диапазонов**.

### TON / монетизация (концепт-экраны по запросу)
- NFT (TEP-62/64), TON Connect, Telegram Mini App как интерактивный слой (deep-link `startapp=`), getgems, оплата Stars; коллекции (фото / пары / morphing-loops / аномалии); роялти; цепочка верификации SHA-256 → CID → NFT hash → Stage-1 baseline; хостинг-уровни HOT/WARM/FOREVER; воронка открытый канал → бот → Mini App FREE → paywall ⭐Stars → NFT → закрытый канал. Ссылка: https://docs.ton.org/

## 7. Ритуалы оценки (формат ответов)

- Пользователь регулярно просит: «на сколько баллов от 0 до 100 … по N категориям/факторам согласно ТЗ» / «реализуй на 99 баллов по 150 (160) факторам».
- Ожидаемый формат: **честные таблицы** — блоки × ~10 факторов, баллы по блокам, Σ-среднее ≈ целевому; плюс **честные оговорки**, что статический макет доказать не может (динамика зума, шрифты в коде, маскировка BLIND и т.п. — в приёмку).
- Известные артефакты генератора (фиксировать при оценке, не выдавать за дизайн): искажения кириллицы, дубль года на плейхеде, подмена имён бинов, уход в чужой домен (CCTV).

## 8. Прочие рабочие правила

- Рукотворная история версий экранов важна: «вспомни первые версии» — откат к одобренной ранней линии (v4→v6) приоритетнее новых ответвлений.
- После инцидента с откатом воркспейса (40+ макетов стёрты как незакоммиченные): **артефакты дизайна коммитим в git** (добавлено исключение `!ui-v4/docs/v5-screens/**/*.png`).

## Приложение A. Факты проекта (из кода/документов; используются в макетах)

- 126 фото; 9 pose-бинов (реальные имена из `pose_policy_v3_9bins.csv`): `left_profile, left_deep, left_mid, left_light, frontal, right_light, right_mid, right_deep, right_profile`.
- Эпохи (`app6/api/ui_fields.py` ERA_BOUNDS): 1999–2007 / 2008–2013 / 2014–2019 / 2020–2026.
- Поля фото (`types.ts`): id, date, t, era, bucket, quality, confidence, boneScore, yaw, pitch, roll, flags.
- Метрики (~24, из репозитория); калибровка median/MAD/p95; FDR 0.05; пороги: quality ≥ 0.50, pose outlier MAD 3.5; статусы «Проходит / Не проходит / Ожидает / Нет данных»; m пар, диагностика при m<20.
- Находки (`timeline_findings.py`): ⚑ elevated, persistent_geometric_change, ↩ baseline return, плотные зоны (≥6 фото, gap 90д) с prune-подсказкой (−3).
- Provenance: имя файла `YYYY_MM_DD[_N]` — единственный авторитет даты; EXIF/claimed — корроборация; sidecar-поля; SHA цепочки → dataset_hash.
- Run manager: included/excluded_count, preflight, статусы complete/failed/cancelled/архив, Retry = новый run, Delete только failed/cancelled.
- Отчёты: public/internal, public_lint, forbidden_terms 0, not_a_verdict.
- Инвентарь датасета `deeputin-dataset-issues-v1.0` (конфликты дат 2, near_duplicate 5, exact_duplicate_link 3, incomplete 1, unknown_pose 0).
- Гипотезы (legacy ledger): 6 223 записей 1998–2026; классы H0_SAME 3 458 / H2_DIFFERENT 430 / H_UNCERTAIN 56 / без класса 2 279; with_rules 875; ручная проверка 134; ретест `pending_missing_current_data` (0%); ограничения model_inferred_3d / high_texture_uncertainty / pose_manual_review; QUARANTINE_POLICY: Stage1/2/3 и публичный отчёт не импортируют/не скорят; доступ opt-in для офлайн-миграции/ретеста.
