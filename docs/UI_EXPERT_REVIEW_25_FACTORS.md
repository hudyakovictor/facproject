# DEEPUTIN — Экспертная оценка интерфейса таймлайна по 25 факторам ТЗ

**Дата:** 2026-08-18
**Ветка:** `arena/01a01526-facproject`
**Предмет оценки:** текущая реализация `ui/` (Timeline V8/V9): `Timeline.tsx`, `App.tsx`, `FrameDetail.tsx`, `PairOverlay.tsx`, `ZoneAtlas.tsx`, `Calibration.tsx`, `Casework.tsx`, `MatrixView.tsx`, `Report.tsx`, `DataIntegrity.tsx`, `ABCompare.tsx`, `PersistenceAnalysis.tsx`, `SessionJournal.tsx`
**Метод:** экспертное ревью кода + прогон сборки/тестов (`npm run verify` — зелёный, 7/7 контрактных тестов) + проверка данных (1909 кадров, 305 пар, 1909 photo-metrics, 567 zone-metrics) против требований ТЗ (`docs/техническое задание проекта/aboutplatform1.txt`, `aboutplatform.txt`).
**Оценка:** по каждому фактору 0–100, где 100 = полностью соответствует ТЗ и удобно для работы аналитика. Итог — среднее арифметическое по 25 факторам.

**Коротко:** ядро таймлайна (сетка, зум, панорама, графики, маркеры, честная работа с данными) реализовано на уровне 75–90 баллов и пригодно для ежедневной аналитической работы. Однако интерфейс пока **отображает извлечённые данные, но не закрывает 5 ключевых сценариев ТЗ**: (1) 3D-инспектор с вращением модели, (2) морфинг двух 3D-моделей с текстурой + тепловая карта с настраиваемыми порогами, (3) сравнение произвольной пары A/B с загрузкой своего фото, (4) байесовский вердикт H0/H1/H2, (5) управление заданиями. Это ровно те блоки, ради которых журналист будет проверять гипотезу о накладках/двойниках, поэтому итоговая оценка — «хорошее ядро, неполный инструмент».

## Оценка удобства анализа и пользования (экспертный разбор)

### Что уже удобно (сильные стороны для рабочего процесса)
1. **Единая X-сетка** — все слои (графики, фото, роли, события, линейка) синхронны. Переход от «графика к фото к паре» не требует пересборки контекста. Это главное достижение V8.
2. **Честность статусов**: «candidate ≠ вердикт» проведена через весь UI (safety-метка, дисклеймеры, «что может опровергнуть»). Для журналиста это защита от самообмана.
3. **Клавиатурный контур**: ←/→ по кадрам, [/] по парам, C — только кандидаты, Enter — детали. При 1909 кадрах это реально ускоряет проход.
4. **Стеки same-day** не ломают сетку (V8-фаза 1) — частая проблема датированных архивов решена правильно.
5. **Persistence-заливки** отличают «устойчивый сдвиг» (главный довод ТЗ) от одиночного скачка одним взглядом.
6. **Empty-state'ы** честно говорят о слабой доказательной базе ракурса (left_deep: 5 пар, right_deep: 3 пары — предупреждение оправдано).

### Что мешает анализу (главные боли)
1. **Нет 3D**: ключевой вопрос «костная структура та же или другая?» приходится решать по z-графикам и таблицам, а не вращением модели. Это самый большой разрыв с ТЗ и с рабочей гипотезой (силиконовые накладки на похожем черепе).
2. **Нет сравнения произвольных пар**: журналист не может взять «2003-01-01 vs 2015-06-15» в одном ракурсе, если пара не была посчитана пайплайном. Для проверки гипотезы «переход между людьми в 2012» это критично.
3. **Один ракурс за раз**: кросс-ракурсная корроборация (та же аномалия в front + profile) требует ручного переключения селектора — многодорожечный режим ТЗ отсутствует.
4. **Текстура свёрнута**: для гипотезы о силиконе/гриме текстурная диагностика — второй по важности слой, а она спрятана в `<details>` и помечена diagnostic-only.
5. **Нет фильтра по периодам**: «показать только 2012–2021» на таймлайне нельзя; только зум.

### Юзабилити (Nielsen, кратко)
- **Узнаваемость**: 9 поз с цветами, чипы-легенды, единая терминология (classifyPair) — хорошо.
- **Эффективность**: хоткеи + minimap + deep-links (URL-хэш) — хорошо; отсутствие кроссхейра от миниатюр и один ракурс за раз — минус.
- **Предотвращение ошибок**: подтверждений при необратимых действиях нет (их и нет — интерфейс read-only), дисклеймеры — плюс.
- **Обучение**: первый запуск без подсказок; легенда символов (◆▲!≈D#) не вынесена в справку — новичку нужен гайд.
- **Доступность**: focus/aria/клавиатура — выше среднего; светлой темы нет, минимальные размеры шрифта 9–10px — на грани.
