# morphing — журнал реализации улучшений (сессия 2026-09-29, партия 1 из N)

> Базовый анализ: `docs/30_MORPHING_ANALYSES.md` (M1–M30). Этот файл — трекер
> того, что из пользовательского списка идей реально реализовано по партиям,
> чтобы не терять нить между сессиями. Решение пользователя: идти по списку
> от простого к сложному, формулировку Forensic Identity Score оставить
> буквально ("вероятность одного человека: XX%"), без смягчающих дисклеймеров.

## Партия 2 — N-лицевой контур: Multi-Face Blend + Timeline

| Идея | Что сделано | Файлы |
|---|---|---|
| Multi-Face Blend (3–4 лица) | Общий бэкенд-эндпоинт `POST /api/morph-multi` (2–6 фото, реконструкция+выравнивание+UV каждого, топология/UV отдаются один раз, + матрица попарных дистанций). Новый унифицированный шейдер `MultiMorphShader.js` (режим 0 = барицентрический блендинг до 4 позиций/текстур). UI: `MultiFaceBlend.jsx` — для 3 лиц интерактивный SVG-барицентрический треугольник (`TriangleBarycentricPicker.jsx`, честная математика барицентрических координат, проверена numeric-тестом), для 4 лиц — упрощённые линейные автонормируемые слайдеры (сознательное упрощение тетраэдрального UI, см. M7). Heatmap "разброса вершин между активными лицами". | `server.py`, `MultiMorphShader.js`, `CanvasMulti.jsx`, `MultiFaceBlend.jsx`, `TriangleBarycentricPicker.jsx` |
| Timeline A→B→C→D (Catmull-Rom) | Переиспользует тот же `/api/morph-multi` (для timeline порядок фото важен, а не веса). Catmull-Rom считается **на GPU** по 4 соседним контрольным точкам текущего сегмента (`u_mode=1` в том же шейдере) — не требует от бэкенда прекомпилировать десятки промежуточных кадров, атрибуты геометрии обновляются только при пересечении границы сегмента. UI: `TimelineMorph.jsx` — загрузка 2–6 фото с изменением порядка (↑/↓), таймлайн-слайдер + автоплей пинг-понг по всей хронологии, метки контрольных точек, heatmap разницы текущего сегмента. | `server.py` (тот же эндпоинт), `MultiMorphShader.js`, `CanvasMulti.jsx`, `TimelineMorph.jsx` |
| Рефакторинг App | `App.jsx` стал тонкой оболочкой с 3 вкладками (Пара / Multi-Face Blend / Timeline); старая логика вынесена в `components/PairMorph.jsx` без функциональных изменений. | `App.jsx`, `components/PairMorph.jsx` |

### Осознанные упрощения (задокументированы в коде)
- **4 лица**: вместо честного тетраэдрального UI — 4 независимых слайдера с автонормировкой суммы к 100%. Полноценный тетраэдральный барицентрический пикер (2D-проекция + слайдер глубины) отложен — сложность UI не оправдана на первой итерации.
- **Timeline-текстура**: кроссфейд только между текстурами двух ближайших исходных фото (start/end сегмента), тогда как форма интерполируется гладким сплайном через 4 точки — общепринятый и малозаметный компромисс (форма "ведёт", текстура "следует").
- Payload `/api/morph-multi` линейно растёт с N (2–6 × ~430 КБ вершин + текстур) — бинарная упаковка (M21) не делалась, ограничение N≤6 в эндпоинте — защита от чрезмерного payload/CPU.

### Как проверялось
- `python3 -m py_compile` на все изменённые `.py`.
- `npm run build` — 43 модуля, без ошибок.
- Расширил временный mock-бэкенд (`/tmp/mock_server.py`, не коммитился) эндпоинтом `/api/morph-multi` с синтетической сеткой; через реальный vite dev + proxy прогнал `curl -F photos=...` на 3 файла — структура ответа (`vertices`, `textures`, `pairwise_mean_dist`) подтверждена.
- Отдельным Node-скриптом проверена корректность барицентрической формулы (A→[1,0,0], B→[0,1,0], C→[0,0,1], центроид→[⅓,⅓,⅓]) и граничные случаи индексации сегментов Catmull-Rom (n=2..4, t на границах и внутри последнего/первого сегмента) — вручную, `node -e`.
- Headless-браузер по-прежнему недоступен в песочнице (нет root для системных зависимостей Chromium) — визуальный рендер в браузере не проверялся автоматически.

## Партия 3 — Facial Symmetry + MP4-экспорт

| Идея | Что сделано | Файлы |
|---|---|---|
| Facial Symmetry Analysis | Новый эндпоинт `POST /api/symmetry` (одно фото): отражение сетки по x=0, зеркальное соответствие через `scipy.spatial.cKDTree` (scipy уже используется в проекте — 3ddfa_v3/app6, не новая зависимость), per-vertex асимметрия, зональные symmetry-score (0-100, эвристический порог, не откалиброван), глобальный score. ## Партия 4 — Temporal Identity Drift + 4D Age Progression

Самый высокий "балл" во всём исходном списке пользователя (Temporal Identity Drift). Реализовано
как расширение уже существующего Timeline (A→B→C→D), а не отдельная фича — они используют одни и
те же N упорядоченных фото.

| Идея | Что сделано | Файлы |
|---|---|---|
| Temporal Identity Drift | `/api/morph-multi` теперь дополнительно возвращает `alpha_id` (80-мерный вектор формы 3DMM) на каждое фото. В `TimelineMorph.jsx` — опциональное поле "год" у каждого фото; при заполнении ≥3 лет строится независимая линейная регрессия по каждой из 80 координат α_id от года (`lib/temporalTrend.js`, `fitAlphaTrend`), считаются остатки (residuals) и аномалии (`residual > mean + 1.5·std`), и "скорость дрейфа формы" `‖slope‖`. | `server.py`, `TimelineMorph.jsx`, `lib/temporalTrend.js` |
| 4D Age Progression | Новый эндпоинт `POST /api/alpha-to-mesh {alpha_id: number[80]}` → строит сетку из произвольного α_id через уже существующий `compute_shape_from_alpha` (из батча 2, ранее unused) + `align_vertices_to_zero`. Фронтенд экстраполирует тренд на "+N лет от последней даты", получает синтетическую сетку и добавляет её последним кадром в timeline — с фиолетовым 🔮-маркером и постоянным предупреждением на экране, что это не фото, а линейная экстраполяция формы (текстура переиспользуется с последнего реального кадра). | `server.py`, `TimelineMorph.jsx` |

### Честные ограничения (заявлены в UI, не спрятаны)
- Линейная регрессия по 80 независимым координатам — не совместная модель; при N<5 точках статистически ненадёжна (сказано в интерфейсе как "ориентир, не вывод").
- 3DMM-регрессия не различает причину геометрического изменения (старение / вес / хирургия / ошибка реконструкции ракурса) — экстраполяция всегда помечена exploratory/synthetic, никогда не показывается как "как будет выглядеть человек".
- Текстура прогнозного кадра — не сгенерирована, а переиспользована с последнего реального фото (иначе потребовалась бы отдельная генеративная модель старения кожи, вне scope этой задачи).

### Как проверялось
- `python3 -m py_compile server.py` — OK; `npm run build` — 45 модулей, без ошибок.
- `node -e` автономная проверка `fitAlphaTrend`: синтетический линейный тренд `α₀ = 2·year + 5` → регрессия восстановила `slope[0] = 2` точно и `predict(2025) = 4055 = 2·2025+5` точно.
- Мок-бэкенд расширен `alpha_id` в `/api/morph-multi` и новым `/api/alpha-to-mesh`; `curl` через vite-прокси подтвердил: `count=3`, `alpha_id` — 3×80 чисел, `/api/alpha-to-mesh` вернул сетку из 35709×3=107163 чисел по округлённому alpha.
- Все новые/изменённые фронтенд-файлы (`App.jsx`, `TimelineMorph.jsx`, `lib/temporalTrend.js`) отдаются dev-сервером Vite с кодом 200 (транформация без ошибок).

## Партия 5 — 3D PCA Scatter пространства лиц (session-only)

| Идея | Что сделано | Файлы |
|---|---|---|
| 3D PCA Scatter + клик-морфинг | Осознанно урезанная версия: без доступа к Stage 1 датасету PCA строится только по лицам, загруженным в текущей сессии Multi-Face Blend (2-4 точки, `data.alpha_id`). `lib/pca.js` — точный PCA через собственные значения/векторы Gram-матрицы N×N (метод Якоби), а не приближённая power-iteration на 80×80 — для N≤6 это тривиально по вычислениям и даёт точное восстановление попарных расстояний. `FaceSpaceScatter.jsx` — сырой Three.js 3D-скаттер (тот же стиль, что CanvasMulti — без r3f/drei, которых нет в зависимостях), клик по точке выставляет 100% вес этому лицу в уже существующем барицентрическом блендере. | `lib/pca.js`, `FaceSpaceScatter.jsx`, `MultiFaceBlend.jsx` |

### Честные ограничения
- Это НЕ 3D-карта всего датасета лиц (как в оригинальной идее M12/M29) — только 2-4 лица текущей сессии. Полноценная версия требует эмбеддингов из Stage 1 pipeline, которые в этой песочнице недоступны (нет весов моделей).
- PCA по ≤4 точкам статистически не означает "главные оси изменчивости лиц" в общем смысле — это просто точное 3D-вложение относительных расстояний между конкретными загруженными лицами. Названо в UI явно: "PCA, эта сессия".

### Как проверялось
- `node --input-type=module` независимый тест `pcaProject`: для N=5 случайных 80-мерных векторов, k=4 компонент → максимальная ошибка восстановления попарных евклидовых расстояний ~1.8e-12 (машинная точность, т.е. метод точный, не приближённый).
- `npm run build` — 47 модулей, без ошибок.
- Файлы `MultiFaceBlend.jsx`, `FaceSpaceScatter.jsx`, `lib/pca.js` отдаются dev-сервером Vite с кодом 200.
