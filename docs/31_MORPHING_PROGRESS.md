# morphing — журнал реализации улучшений (сессия 2026-09-29, партия 1 из N)

> Базовый анализ: `docs/30_MORPHING_ANALYSES.md` (M1–M30). Этот файл — трекер
> того, что из пользовательского списка идей реально реализовано по партиям,
> чтобы не терять нить между сессиями. Решение пользователя: идти по списку
> от простого к сложному, формулировку Forensic Identity Score оставить
> буквально ("вероятность одного человека: XX%"), без смягчающих дисклеймеров.

## Партия 1 — «быстрые победы» (эта сессия)

| Идея из списка | Что сделано | Файлы |
|---|---|---|
| UV Diff (текстурный diff) | Новый режим шейдера `u_showUVDiff`: `abs(texA-texB)` по палитре heatmap, независим от прогресса морфа формы. Чекбокс в UI. | `MorphShader.js`, `Controls.jsx`, `App.jsx`, `Canvas3D.jsx` |
| Morphability Score — предупреждение | Баннер в UI при score < 40%: лица сильно различаются, морфинг может выглядеть неестественно + честная пометка "эвристика, не откалибровано по датасету" (константа 0.15 не менялась — калибровка по σ датасета отложена, требует Stage 1 источник, см. M10/M29 в 30_MORPHING_ANALYSES). | `App.jsx` |
| Quantitative similarity (`/api/similarity`) | Добавлены: zone breakdown (7 зон), top-5 наиболее расходящихся зон, `cosine_similarity_alpha_id` (косинус по 80-мерному вектору формы alpha_id — точнее прежнего косинуса по плоским вершинам). Эндпоинт теперь реально используется фронтендом (раньше был мёртвым, см. M2 в 30_MORPHING_ANALYSES) — панель `SimilarityPanel`. | `server.py`, `App.jsx` |
| Forensic Identity Score — "вероятность одного человека" | По явному решению пользователя формулировка буквальная: `probability_same_person`, глобальный score = взвешенная сумма по 7 зонам (веса в `_FORENSIC_ZONE_WEIGHTS`). Добавлено текстовое объяснение по зонам ("да"/"нет"/"нейтрально") на основе `z_local` — **локального** z-score внутри 7 зон одной пары (НЕ откалиброванная по датасету σ — это осталось открытым пунктом M10/M13). | `server.py`, `App.jsx` |
| Identity Decomposition (`V = V_mean + tA·δA + tB·δB`) | Новый бэкенд-эндпоинт `GET /api/mean-face` (среднее лицо BFM = `fm.u`, константа модели, кэшируется). Новая функция `get_mean_face_vertices()` в `app8/reconstruction.py` и `align_vertices_to_zero()` в `aligner.py`. Шейдер: атрибуты `positionMean/deltaA/deltaB`, uniforms `u_decompMode/u_tA/u_tB`, режим блендинга текстуры по `tB/(tA+tB)` в decomposition-режиме. UI: чекбокс + 2 слайдера + пресеты (Только A / Только B / Среднее лицо / A+B). Heatmap теперь имеет 3 источника: `|A-B|`, `|δA|` (уникальность A), `|δB|` (уникальность B). | `app8/reconstruction.py`, `aligner.py`, `server.py`, `MorphShader.js`, `Canvas3D.jsx`, `Controls.jsx`, `App.jsx` |
| Live-метрики в реальном времени | Уже существовали (mean/max/%/cosine/morphability на каждый тик слайдера) — без изменений в этой партии. | — |

### Как проверялось (в песочнице нет torch/весов 3DDFA-V3 — реальная реконструкция недоступна)
- `python3 -m py_compile` на все изменённые `.py`.
- Чистая математика (`_zone_breakdown`, веса, z_local) прогнана на синтетических векторах вне FastAPI — числа и топ-5/объяснения ведут себя как ожидалось (см. `/tmp/test_zone.py`, не коммитился).
- `npm run build` фронтенда — сборка проходит без ошибок (37 модулей).
- Полный runtime smoke-тест: временный mock-бэкенд (`/tmp/mock_server.py`, не коммитился) с синтетической сеткой 189×189 вершин, отдающий те же JSON-схемы, что и `server.py` — через реальный vite dev + proxy `/api`, curl проверил все 4 эндпоинта (`/api/health`, `/api/mean-face`, `/api/morph-pair`, `/api/similarity`, `/api/forensic-score`) на структурное соответствие тому, что читает `App.jsx`.
- Headless-браузер (Playwright/Chromium) в песочнице недоступен (нет root для системных зависимостей) — визуальный рендер шейдера в браузере не проверялся автоматически, только код-ревью шейдера построчно.

### Что осталось открытым из этой партии
- Реальная калибровка Morphability Score / z_local по σ same-day noise floor (M10) — нужен доступ к Stage 1 выводам (`DEEPUTIN_STAGE1_ROOT`, M29), не делали.
- Настоящий анатомический атлас зон вместо диапазонов индексов вершин (M13, зависит от фикса K21–K23 в `stage2_v2`).
