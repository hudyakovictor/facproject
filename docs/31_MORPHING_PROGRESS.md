# morphing — журнал реализации улучшений (сессия 2026-09-29, партия 1 из N)

> Базовый анализ: `docs/30_MORPHING_ANALYSES.md` (M1–M30). Этот файл — трекер
> того, что из пользовательского списка идей реально реализовано по партиям,
> чтобы не терять нить между сессиями. Решение пользователя: идти по списку

### Как проверялось (в песочнице нет torch/весов 3DDFA-V3 — реальная реконструкция недоступна)
- `python3 -m py_compile` на все изменённые `.py`.
- Чистая математика (`_zone_breakdown`, веса, z_local) прогнана на синтетических векторах вне FastAPI — числа и топ-5/объяснения ведут себя как ожидалось (см. `/tmp/test_zone.py`, не коммитился).
- `npm run build` фронтенда — сборка проходит без ошибок (37 модулей).
- Полный runtime smoke-тест: временный mock-бэкенд (`/tmp/mock_server.py`, не коммитился) с синтетической сеткой 189×189 вершин, отдающий те же JSON-схемы, что и `server.py` — через реальный vite dev + proxy `/api`, curl проверил все 4 эндпоинта (`/api/health`, `/api/mean-face`, `/api/morph-pair`, `/api/similarity`, `/api/forensic-score`) на структурное соответствие тому, что читает `App.jsx`.
- Headless-браузер (Playwright/Chromium) в песочнице недоступен (нет root для системных зависимостей) — визуальный рендер шейдера в браузере не проверялся автоматически, только код-ревью шейдера построчно.

### Что осталось открытым из этой партии

- Настоящий анатомический атлас зон вместо диапазонов индексов вершин (M13, зависит от фикса K21–K23 в `stage2_v2`).

## Партия 2 — N-лицевой контур: Multi-Face Blend + Timeline

| Идея | Что сделано | Файлы |
|---|---|---|
| Multi-Face Blend (3–4 лица) | Общий бэкенд-эндпоинт `POST /api/morph-multi` (2–6 фото, реконструкция+выравнивание+UV каждого, топология/UV отдаются один раз, + матрица попарных дистанций). Новый унифицированный шейдер `MultiMorphShader.js` (режим 0 = барицентрический блендинг до 4 позиций/текстур). UI: `MultiFaceBlend.jsx` — для 3 лиц интерактивный SVG-барицентрический треугольник (`TriangleBarycentricPicker.jsx`, честная математика барицентрических координат, проверена numeric-тестом), для 4 лиц — упрощённые линейные автонормируемые слайдеры (сознательное упрощение тетраэдрального UI, см. M7). Heatmap "разброса вершин между активными лицами". | `server.py`, `MultiMorphShader.js`, `CanvasMulti.jsx`, `MultiFaceBlend.jsx`, `TriangleBarycentricPicker.jsx` |
| Timeline A→B→C→D (Catmull-Rom) | Переиспользует тот же `/api/morph-multi` (для timeline порядок фото важен, а не веса). Catmull-Rom считается **на GPU** по 4 соседним контрольным точкам текущего сегмента (`u_mode=1` в том же шейдере) — не требует от бэкенда прекомпилировать десятки промежуточных кадров, атрибуты геометрии обновляются только при пересечении границы сегмента. UI: `TimelineMorph.jsx` — загрузка 2–6 фото с изменением порядка (↑/↓), таймлайн-слайдер + автоплей пинг-понг по всей хронологии, метки контрольных точек, heatmap разницы текущего сегмента. | `server.py` (тот же эндпоинт), `MultiMorphShader.js`, `CanvasMulti.jsx`, `TimelineMorph.jsx` |
| Рефакторинг App | `App.jsx` стал тонкой оболочкой с 3 вкладками (Пара / Multi-Face Blend / Timeline); старая логика вынесена в `components/PairMorph.jsx` без функциональных изменений. | `App.jsx`, `components/PairMorph.jsx` |

### Осознанные упрощения (задокументированы в коде)
- **4 лица**: вместо честного тетраэдрального UI — 4 независимых слайдера с автонормировкой суммы к 100%. Полноценный тетраэдральный барицентрический пикер (2D-проекция + слайдер глубины) отложен — сложность UI не оправдана на первой итерации.
- **Timeline-текстура**: кроссфейд только между текстурами двух ближайших исходных фото (start/end сегмента), тогда как форма интерполируется гладким сплайном через 4 точки — общепринятый и малозаметный компромисс (форма "ведёт", текстура "следует").
- Payload `/api/morph-multi` линейно растёт с N (2–6 × ~430 КБ вершин + текстур) — бинарная упаковка (M21) не делалась, ограничение N≤6 в эндпоинте — защита от чрезмерного payload/CPU.

### Как проверялось
- `python3 -m py_compile` на все изменённые `.py`.
- `npm run build` — 43 модуля, без ошибок.
- Расширил временный mock-бэкенд (`/tmp/mock_server.py`, не коммитился) эндпоинтом `/api/morph-multi` с синтетической сеткой; через реальный vite dev + proxy прогнал `curl -F photos=...` на 3 файла — структура ответа (`vertices`, `textures`, `pairwise_mean_dist`) подтверждена.
- Отдельным Node-скриптом проверена корректность барицентрической формулы (A→[1,0,0], B→[0,1,0], C→[0,0,1], центроид→[⅓,⅓,⅓]) и граничные случаи индексации сегментов Catmull-Rom (n=2..4, t на границах и внутри последнего/первого сегмента) — вручную, `node -e`.
- Headless-браузер по-прежнему недоступен в песочнице (нет root для системных зависимостей Chromium) — визуальный рендер в браузере не проверялся автоматически.

## Партия 3 — Facial Symmetry + MP4-экспорт

| Идея | Что сделано | Файлы |
|---|---|---|
| Facial Symmetry Analysis | Новый эндпоинт `POST /api/symmetry` (одно фото): отражение сетки по x=0, зеркальное соответствие через `scipy.spatial.cKDTree` (scipy уже используется в проекте — 3ddfa_v3/app6, не новая зависимость), per-vertex асимметрия, зональные symmetry-score (0-100, эвристический порог, не откалиброван), глобальный score. Ответ **намеренно** имеет ту же схему, что `/api/morph-pair` (vertices_a/b = оригинал/зеркальное-соответствие) — это позволило переиспользовать существующий `Canvas3D`/`MorphShader` без единой новой строчки шейдера: heatmap "diff" уже и есть карта асимметрии. Новая вкладка `SymmetryMode.jsx` с zone-панелью и честной оговоркой в UI ("BFM — статистическая модель, асимметрия частично замыта усреднением выборки"). | `server.py`, `SymmetryMode.jsx`, `App.jsx` |
| MP4-экспорт (доп. к WebM) | `handleDownloadWebm` в `PairMorph.jsx` теперь пробует `video/mp4;codecs=avc1...` через `MediaRecorder.isTypeSupported` (Safari/свежий Chrome-Edge умеют кодировать H.264 нативно в браузере), с фолбэком на WebM/VP9 → WebM. Расширение файла и MIME подбираются автоматически. Серверный ffmpeg-пайплайн сознательно НЕ добавлен — он тянет системную зависимость деплоя ради формата, который браузер в большинстве актуальных версий и так может отдать сам (M9 в 30_MORPHING_ANALYSES.md). | `PairMorph.jsx`, `Controls.jsx` |

### Как проверялось
- `python3 -m py_compile` на изменённые `.py`.
- `npm run build` — 44 модуля, без ошибок.
- Mock-бэкенд расширен `/api/symmetry`; `curl -F photo=...` через vite dev proxy подтвердил структуру ответа и корректную загрузку `SymmetryMode.jsx` по HTTP 200.
- MP4/WebM-логика не тестировалась в реальном браузере (нет headless Chromium в песочнице) — код-ревью `MediaRecorder.isTypeSupported` цепочки кандидатов, поведение идентично уже работавшей WebM-ветке (M3 прошлой сессии), только добавлен приоритет MP4 и авто-выбор расширения.
