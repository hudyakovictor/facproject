# DEEPUTIN — Подготовка проекта для журналиста-расследователя

**Дата:** 2026-08-18 · **Ветка:** `arena/01a01526-facproject`
**Тема расследования:** теория двойников В. Путина / гипотеза о силиконовых накладках на людях со схожей формой черепа
**Данные:** фотоархив 1999–2026, 9 ракурсов, хронологический анализ

> ⚠️ Этот документ — техническая карта проекта, а не выводы расследования.
> Система не выдаёт вердикт «разные люди»: она производит **кандидатов**,
> каждый из которых требует независимой корроборации (другие ракурсы,
> периоды, экспертный просмотр, внешние публикации).

## 1. Что уже готово: данные извлечены и загружены в интерфейс

Все данные пайплайна (Stage 1 + Stage 2) лежат в `ui/public/data/` и
отображаются интерфейсом (`ui/`). Проверено: сборка зелёная, контракт данных
валиден, все 4 файла отдаются сервером.

| Файл | Объём | Содержимое |
|---|---|---|
| `main_timeline.csv` | **1909 кадров** | дата, ракурс (pose_bin), yaw/pitch/roll, датировка+provenance, near-duplicate, статусы геометрии/сегментации/UV, покрытие, хронологические индексы |
| `photo_metrics.json` | **1909 записей** | alignment, резкость (Laplacian), шум, экспрессия, улыбка/челюсть, качество кожи, аутентичность кожи (z), анизотропия, hard-area — поля заполнены на 99,8–100% |
| `pair_metrics.json` | **305 пар** | adjacent (132) + baseline (123) + rolling_anchor (50); RMSE/Median/P95/point-to-plane, robust-z (5 метрик), калибровка, FDR (q-value), мимика A/B, видимость, выравнивание |
| `zone_metrics.json` | **567 строк** (63 пары × 9 зон) | зональный raw rmse/median/p95 по сетке 3×3; robustZ зон некалиброван (insufficient_calibration) — UI честно показывает raw rmse |

**Ключевые цифры для расследования:**
- **18 пар** со статусом `persistent_geometric_change` — устойчивое геометрическое изменение (главный тип аномалии ТЗ);
- **34 пары** `coherent_jump_candidate` — согласованный скачок;
- **242 пары** `residual_pose_mismatch` — остаточное несовпадение позы (не кандидаты, но источник шума);
- **11 пар** `insufficient_calibration` — калибровки недостаточно, вывод невозможен;
- **52 пары** проходят порог **FDR10** (q ≤ 0.10) — сигнал не объясняется множественным тестированием;
- **near-duplicate кадры и конфликты датировки в текущем экспорте отсутствуют** (0 кадров с `near_duplicate_of`, 0 с `date_conflict_sources`) — механизмы отображения готовы (значки ≈ и D на таймлайне) и сработают при переизвлечении архива; датировка всех кадров сейчас — из имён файлов (`filename_only`).

### Плотность по эпохам (кадров на ракурс)

| Эпоха | frontal | left_* | right_* |

## 3. Как интерфейс отображает данные (карта экранов)

| Раздел интерфейса | Что показывает | Для чего журналисту |
|---|---|---|
| **Таймлайн** (главный экран) | 6 слоёв: геометрия пар → поддержка → применимость → качество → фото → роли/события → линейка годов. Фильтр ракурса, слоёв, зум/панорама, minimap, кластеры кандидатов | Основной рабочий инструмент: хронологический проход по ракурсу |
| **Детали кадра** (клик по фото, Enter) | crop, применимость, поза, датировка/provenance, диагностика кожи | Проверка конкретного фото: качество, дата, видимость |
| **Попап пары** (клик по точке на графике) | A/B рядом, дельта align/z, мимика, 11 гейтов (поза→видимость→выравнивание→мимика→качество→калибровка→FDR→геометрия), топ-зоны, «что опровергнет кандидатуру» | Разбор каждого кандидата: почему он кандидат и что его опровергает |
| **Проверка кандидатов** (Разделы → Очередь) | Все 52 FDR-пары всех ракурсов, сортировка по evidence-score, решения «к отчёту/артефакт/нужны данные» (клавиши 1/2/3) | Дисциплинированный разбор всех кандидатов без пропусков |
| **Корроборация** (Разделы → Корроборация) | Годы × ракурсы: годы, где кандидаты в ≥2 ракурсах (независимое подтверждение) | Главный фильтр достоверности: сигнал в одном ракурсе — слабо, в нескольких — сильно |
| **Зональный атлас** | 3×3 зоны по парам, средняя RMSE по зонам | Локализация различий: где именно «не сходится» лицо |
| **Калибровка** | Распределение robust-z по семействам пар, статусы калибровки зон | Понимание шума метода: что есть «норма» для данного семейства |
| **Persistence** | Цепочки подряд идущих FDR-кандидатов | Устойчивый сдвиг ≠ одиночный скачок — ключевой довод ТЗ |
| **Отчёт** | Экспорт HTML/CSV/PDF принятых к отчёту кандидатов с ограничениями | Черновик для будущей публикации |
| **Целостность данных** | Покрытие по ракурсам, orphan-пары, null-статистика, исключённые поля | Аудит: чему можно верить в данных |

## 4. Рабочий процесс анализа (пошаговый протокол для журналиста)

**Шаг 0 — аудит данных.** Откройте «Целостность данных»: проверьте покрытие
по ракурсам. Запомните: deep/mid ракурсы слабые, frontal — основной.

**Шаг 1 — хронологический проход по анфасу.** В таймлайне выберите
«Анфас». Пройдите 1999→2026 клавишами ←/→, включите слои «Геометрия пар» и
«События». Отмечайте зоны, где точки пар (◆/▲) сгущаются — это периоды
предполагаемых изменений. Кластеры кандидатов продублированы закладками на
minimap.

**Шаг 2 — разбор кандидатов.** Включите «только кандидаты» (клавиша C) и
проходите пары клавишами [/]. Для каждой — попап (Enter): проверьте
последовательно гейты. Кандидат силён, если: калибровка elevated + FDR10 +
видимость ≥50% + мимика совпадает + есть persistence + подтверждение в
другом ракурсе.

**Шаг 3 — очередь.** Откройте «Проверка кандидатов» — все FDR-пары всех
ракурсов. Решения 1/2/3; рациональные решения записывайте. Экспортируйте
журнал решений.

**Шаг 4 — корроборация.** Откройте «Корроборация»: годы с подсветкой —
кандидаты в ≥2 ракурсах. Это ядро будущих тезисов: одинарный сигнал может
быть артефактом, двойной/тройной — уже закономерность.

**Шаг 5 — локализация.** Для сильных кандидатов откройте «Зональный атлас»:
в каких зонах (переносица/глазницы/скулы/челюсть — костные; губы/щёки —
мягкие) локализовано различие. Различие в костных зонах при совпадении
профильного контура — согласуется с гипотезой накладок; различие по всему
лицу сразу — скорее другой человек или артефакт.

**Шаг 6 — persistence.** Проверьте цепочки: изменение, удержавшееся годы
(2012→2021), — сильный довод в пользу смены; скачок «туда-обратно»
(возврат) — довод в пользу чередования носителей.

**Шаг 7 — отчёт.** Принятые к отчёту кандидаты экспортируйте (HTML/CSV/PDF)
и сверьте с внешними публикациями (британская разведка, заявления СБУ,
японские исследователи, В. Соловей, генерал СВР): совпадения периодов
повышают доверие к данным.

**Шаг 8 — хронологическая рамка гипотезы.** Сопоставьте находки с рабочей
моделью: 1999–2012 (оригинал) → 2012–2021 (смена) → 2021–2026 (ещё смена),
с возможными периодами смешения. Отметьте, какие данные её поддерживают, а
какие противоречат — **ищите опровержения, а не подтверждения**.

## 5. Текущие ограничения (что интерфейс ещё не умеет — план P0)

По итогам экспертной оценки (`docs/UI_EXPERT_REVIEW_25_FACTORS.md`, 58/100)
для полной проверки гипотезы о накладках не хватает пяти блоков ТЗ:

1. **3D-инспектор** — вращение реконструированной модели лица (в старой
   ui-v2 был three.js MeshViewer на полной BFM-топологии; в текущий UI не
   портирован).
2. **Морфинг двух 3D-моделей с текстурой + тепловая карта** с настраиваемыми
   порогами (попап настроек: 0–25% сине-голубой, 25–50% к зелёному, 50–75%
   к красному, >75% тёмно-красный).
3. **Сравнение произвольной пары** — выбор любых двух фото из базы (с
   использованием уже извлечённых 3D-моделей) или загрузка своего фото (без
   добавления в базу); проценты различий по геометрии/текстуре/каждой
   метрике.
4. **Текстурная панель** — вероятность силикона 0–1, LBP, блеск, плотность
   пор (данные должен отдавать Stage 1).
5. **Байесовский вердикт H0/H1/H2** — распределение вероятностей по трём
   гипотезам с обоснованием (геометрия/текстура/хронология).

Инфраструктурные требования для запуска этих блоков: веса моделей 3DDFA_V3
(`assets/net_recon.pth` и др., ~300 МБ), реальный фотоархив и извлечённые
изображения на `/Volumes/SDCARD/storage/stage1` (в песочнице недоступны —
миниатюры заменяются цветом позы, что интерфейс делает штатно).

## 6. Риски интерпретации (обязательно к прочтению перед выводами)

1. **Качество фото ≠ силикон.** Ранние годы шумные, поздние — детальные.
   Если бы алгоритм игнорировал качество, он бы «находил» силикон в 90-х и
   «настоящую кожу» в 2024–2025. Текущий пайплайн калибрует текстурные
   метрики (skinAuthenticityScore — z-оценка против калибровочного эталона),
   но текстурные метрики помечены diagnostic-only: сами по себе они **не**
   являются identity-evidence.
2. **Zone robustZ некалиброван** (insufficient_calibration, медианы ~2.8e6).
   Интерфейс намеренно показывает raw rmse и никогда не выдаёт его за z.
3. **Даты из имён файлов** (filename_only, 100% кадров) — provenance
   указывается честно; при появлении конфликтов (EXIF vs имя файла) кадр
   помечается значком D, механизм готов, в текущем экспорте таких кадров 0.
4. **Скачки значений по хронологии — ожидаемы** по рабочей гипотезе: разные
   люди в разные годы + разные версии накладок + улучшение накладок со
   временем. Разрозненные скачки сами по себе не доказывают смену — нужны
   persistence и корроборация.
5. **Слабые ракурсы** (deep/mid) — до 5–14 пар; выводы по ним только
   вспомогательные.
6. **FDR-значимость ≠ факт**: 52 пары прошли FDR10, но каждая требует
   ручной проверки (раздел «Проверка кандидатов»).

## 7. Глоссарий (для журналиста)

| Термин | Значение |
|---|---|
| Кандидат (candidate) | Пара фото, где геометрическое различие превысило калибровочный порог. **Не вердикт.** |
| Persistent | Устойчивое изменение: цепочка соседних кандидатов во времени. |
| FDR10 | Контроль множественных сравнений (q ≤ 0.10): сигнал не объясняется «перебрали много пар». |
| Robust z | Насколько измерение пары отклоняется от калибровочной нормы (в сигмах). |
| Baseline / rolling_anchor | Семейства пар: от первого кадра ряда / от скользящего якоря. |
| Pose bin | Один из 9 ракурсов (фронт, 3/4 light/mid/deep, профиль — слева/справа). |
| Adjacent | Пара соседних по времени кадров в одном ракурсе. |
| Persistence-цепочка | Серия подряд идущих кандидатов — «сдвиг удержался во времени». |
| near-duplicate | Почти идентичный кадр (по перцептивному хешу). |
| Provenance даты | Откуда дата: имя файла / EXIF / конфликт источников. |
| Skin authenticity (z) | Z-отклонение текстурных характеристик кожи от эталона. Diagnostic-only. |
