## Ключевое требование: переход не должен быть равномерным

Прежняя реализация (`heatColor`) жёстко задавала пять цветов и линейно
интерполировала между ними — настраивались только позиции. Требовалось
другое: **разный характер перехода на разных участках**.

Введён параметр `sharpness ∈ [0,1]` **на каждый сегмент**:

```
sharpness = 0    ──────╱──────    плавно по всей ширине сегмента
sharpness = 0.85 ─────┤▌├─────    резкий переход в узкой полосе
sharpness = 1    ─────┤│├─────    ступенька: либо ниже порога, либо выше
```

Математически: активная полоса перехода сжимается к середине сегмента, её
ширина = `1 - sharpness`. За пределами полосы цвет удерживается.

### Пресет по умолчанию

| Позиция | Цвет | Резкость | Смысл |
|---|---|---|---|
| 0.00 | синий | 0.00 | норма |
| 0.25 | голубой | 0.15 | верх нормы — переход плавный |
| 0.50 | жёлтый | 0.55 | внимание |
| 0.75 | красный | **0.85** | граница аномалии — переход резкий |
| 1.00 | тёмно-красный | — | предел, цвет удерживается |

Дополнительно есть пресеты «Линейный» и «Жёсткий порог» (ступенька в
середине шкалы).

## Панель `HeatmapWorkbench`

Карта и настройки **рядом**, как вы просили: эффект правки виден немедленно.

**Слева:**
* 3D-карта различий A↔B (полный BFM-меш или облако точек);
* **гистограмма распределения** различий, окрашенная тем же градиентом —
  сразу видно, сколько точек попадает в каждую цветовую зону;
* счётчики по классам и числовая легенда шкалы.

**Справа — редактор:**
* живое превью шкалы с числовыми подписями в единицах метрики;
* **кривая перехода** — накопленное изменение цвета по шкале. Крутой участок
  = резкий переход. Делает `sharpness` наглядным, а не абстрактным числом;
* по остановке: цвет (нативный color-picker), позиция, резкость, удаление;
* добавление остановки — в самый широкий промежуток, без наслоения точек;
* верх шкалы (`maxReference`) — значение метрики для правого края;
* **отметки порогов классификации точек** прямо на шкале: видно, где
  проходит граница «допустимо / аномально» относительно цветов.

## Главный инвариант: превью = результат

Редактор и раскраска меша вызывают **одну и ту же** функцию
`evaluateGradient`. Расхождения между «как настроено» и «как выглядит» быть
не может по построению. Закреплено тестом.

---

## Защита от некорректных настроек

Ошибка в настройке не должна ронять рендер 35 709 вершин:

* некорректный цвет → серый вместо исключения;
* позиции и резкость зажимаются в `[0,1]`;
* неотсортированные остановки упорядочиваются;
* сегмент нулевой ширины = мгновенный скачок цвета (легальный приём);
* градиент всегда покрывает всю шкалу `[0,1]` — края не остаются
  неопределёнными;
* минимум две остановки: кнопка удаления блокируется.

## Бэкенд

Секция `gradient` в настройках (`GET/PUT /api/v1/settings`) с позициями,
цветами, резкостью и подписями. Прежние `heatmap.stop_*` сохранены для
обратной совместимости; предусмотрена миграция `fromLegacyStops`.

Слияние с умолчаниями (добавленное на предыдущем шаге) корректно подхватило
новую секцию в уже существующих файлах настроек — проверено сквозным
прогоном: PUT сохраняет резкость `0.95`, `reset` возвращает `0.55`.

## Оставшийся долг

1. **Перетаскивание остановок мышью** по полосе превью — сейчас позиция
   задаётся слайдером.
2. **Именованные пользовательские пресеты** — сохраняются только текущий
   градиент, набор своих схем завести нельзя.
3. **Синхронизация с `landmark_shift`** односторонняя: пороги точек
   отображаются на шкале, но сдвиг остановки не меняет пороги
   классификации — это осознанно, чтобы правка палитры не меняла критерии
   анализа.
4. Гистограмма строится по видимым точкам пары; для полного меша
   (35 709 вершин) она пока не учитывает per-vertex residuals.
