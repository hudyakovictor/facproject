# Настройки, которые ни на что не влияли: пункты №8 и №9

**Дата:** 2026-07-30
**Основание:** `ui/AUDIT_50_TOP30.md` — два пункта с наивысшим оставшимся
баллом (94 и 93).
**Закрыто:** 2 пункта. Открытых из топ-30 остаётся 13.

---

## Суть дефекта

Интерфейс предлагал восемь органов управления, ни один из которых не менял
результат:

| Настройка | Что было |
|---|---|
| `detail_level` (простой / стандартный / экспертный) | Ни один компонент его не читал |
| `confidence_min` | Не читался |
| `quality_min` | Не читался; фильтр «скрыть низкое качество» сравнивал с вшитым `0.35` |
| `geometry_zone_delta_limit` | `ComparisonPanel` считал по вшитому `0.018` |
| `texture_zone_delta_limit` | То же, вшитый `0.04` |
| `expression_smile`, `expression_jaw_open` | Не читались |

Показательна деталь: в `ComparisonPanel` стояла таблица

```js
const POLICY_DELTA = {
  bone: 0.018, orbit: 0.018, ...,
  sil: 0.04, spec: 0.04, ...,
};
```

Это **буквально копия дефолтов** `geometry_zone_delta_limit` и
`texture_zone_delta_limit` из `app6/api/settings.DEFAULT_SETTINGS`,
перенесённая в код. Пользователь двигал ползунок, значение уходило на диск
через `PUT /api/v1/settings`, а сравнение продолжало считать по константе.

Отдельно: `App.tsx` передавал в модалку `onApplied={() => undefined}` —
даже успешное сохранение никак не отражалось на текущем сеансе.

**Почему это серьёзно.** `app6/AGENTS.md` запрещает интерфейсу заявлять
возможности, которых нет. Здесь следователь ужесточает порог, видит
неизменившийся результат и заключает, что расхождение устойчиво к
ужесточению критерия. Вывод ложный, а проверить его по интерфейсу нельзя.

---

## Решение

`ui/src/settings.tsx` — контекст настроек по образцу существующего
`BaselineContext`.

```
App                       ← только провайдеры
└── SettingsProvider      ← грузит GET /api/v1/settings один раз
    └── AppInner          ← useThresholds(), useSettings().apply
        ├── ComparisonPanel   → лимиты дельт
        ├── PairKeysPanel     → состав вкладок по detail_level
        └── SettingsModal     → onApplied обновляет контекст
```

### Что теперь работает

| Настройка | Влияние |
|---|---|
| `geometry_zone_delta_limit` | Порог превышения для 6 геометрических метрик в сравнении диапазонов |
| `texture_zone_delta_limit` | То же для 6 текстурных |
| `quality_min` | Граница «низкого качества» в фильтре выборки |
| `confidence_min` | Нижняя граница уверенности; ползунок фильтра может ужесточить, но не ослабить ниже неё |
| `detail_level` | Состав категорий в панели метрик пары |

Раскладка уровней детализации:

* **простой** — A (статзначимость) и C (качество): без них вывод читать
  нельзя вообще;
* **стандартный** — плюс B, D, E, F: содержательные измерения;
* **экспертный** — плюс G, H, I: провенанс, хэши, служебные ключи.

Подпись под переключателем объясняет это прямо в модалке — иначе
пользователь не поймёт, что именно изменилось.

`expression_smile` / `expression_jaw_open` **осознанно не подключены**:
это пороги QC мимики, применяемые Stage 2 при построении пары. Применять
их повторно в интерфейсе означало бы фильтровать уже отфильтрованное и
расходиться с пайплайном. Пороги остаются в настройках как параметр
следующего прогона; в панели ключей видны фактические
`expression_qc_threshold` и `expression_qc_status` этой пары.

## Разобранная ловушка

Первая версия обернула провайдером содержимое `App`, а не сам `App`.
Компонент при этом остаётся **над** провайдером в дереве, поэтому его
собственный `useThresholds()` читал бы значения по умолчанию всегда — при
работающем backend и корректных настройках. Дефект тихий: тесты на
провайдер прошли бы, а фильтрация выборки молча игнорировала бы пороги.

Исправлено разделением на `App` (только провайдеры) и `AppInner` (логика).

Второе: нормализация порогов не может использовать `value || default` —
ноль является валидным значением («не фильтровать»), и такое выражение
подменило бы осознанный 0 дефолтом. Используется явная проверка
`typeof value === "number" && Number.isFinite(value)`; тест
«нулевой порог сохраняется, а не подменяется дефолтом» это фиксирует.
