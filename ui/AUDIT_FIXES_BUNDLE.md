## Найденный дефект: выдуманные «соседние кадры»

Работа над выносом генератора вскрыла проблему серьёзнее размера бандла.

`LeftPanel → ContextTab` строил список соседних кадров так:

```tsx
const idx = PHOTOS.findIndex(p => p.id === photo.id);
const neighbors = PHOTOS.slice(Math.max(0, idx - 4), ...);
```

`PHOTOS` — **встроенный синтетический демо-набор**, а не показанные
данные. В research-режиме это означало: пользователь открывает реальный
кадр, переходит на вкладку «Контекст» и видит рядом четыре кадра до и
четыре после — **выдуманные, с синтетическими метриками и датами**.
Причём `findIndex` по реальному ID возвращал `-1`, то есть срез брался
от начала демо-массива: соседями произвольного кадра 2015 года
оказывались первые кадры 1999-го.

Это ровно та подмена, которую запрещает `app6/AGENTS.md`. Исправлено:
`photos` пробрасывается в `LeftPanel` пропсом, соседи берутся из текущего
набора. Добавлена защита от деления на ноль при пустом списке.

## Вынос генератора

`src/demoData.ts` — новый модуль, загружаемый **только** динамическим
импортом из ветки «backend недоступен»:

```ts
export async function loadDemoPhotos(): Promise<Photo[]> {
  const module = await import("./demoData");
  return module.buildDemoPhotos();
}
```

Результат сборки: `demoData-EF2rh2zS.js` — 3.58 kB (1.77 kB gzip),
отдельным чанком. При работающем backend не скачивается и не исполняется.

### Что пришлось разделить

Вырезание по границам функций задело три **нормативные** константы,
стоявшие рядом с генератором: `POSE_BUCKETS`, `POSE_YAW`, `POSE_LABELS`.
Это раскладка девяти ракурсов, которой оперирует весь пайплайн, — она
возвращена в `data.ts` с пояснением, почему не является демо-данными.

### `REF`: из вычисляемого в статическое

`REF` строился функцией `refMedians()`, которая **прогоняла весь
демо-массив из 1809 объектов на старте модуля**. Это заставляло генератор
исполняться при каждой загрузке страницы — в том числе при рабочем
backend, когда демо-данные не нужны.

Значения детерминированы (seeded PRNG), поэтому зафиксированы как
константы. Риск такой замены очевиден: если генератор изменится, таблица
молча разойдётся с ним, и baseline демо-режима начнёт считаться от
неверных медиан. Поэтому добавлен страж
`demoData.test.ts::REF соответствует генератору` — пересчитывает медианы
и разбросы из фактического набора и сверяет с таблицей.

### Мёртвый код

`buildTrack()` (28 строк) не использовался нигде за пределами `data.ts` —
удалён вместе с `refMedians()`.

## Начальное состояние `App`

`useState<Photo[]>(PHOTOS)` заменено на `useState<Photo[]>([])`.

Показывать синтетические кадры до ответа backend значит выдавать их за
данные: до загрузки таймлайн был заполнен демо-набором **без пометки
demo**, потому что `dataMode` в этот момент ещё `loading`. Теперь до
ответа выборка пуста, а демо-набор приходит из `refreshTimeline` уже с
честным `mode: "demo"`.
