# Real Data Examples

Эта папка содержит **реальные результаты** работы пайплайна DEEPUTIN на конкретном наборе фотографий.  
Здесь вы можете посмотреть, как выглядят данные "вживую", без моков.

## Что здесь лежит

### stage1/ — пример одной фотографии (фронтальный ракурс)

Исходник: `/Volumes/SDCARD/photo/main/1999_09_01.jpg`  
Результат обработки: папка `1999_09_01__fdfba9d7bcd5/`

**Файлы:**
- `info.json` — все метаданные фотографии: углы, ракурс, качество, landmarks, кожа
- `ldm106_raw.csv` — 106 сырых landmarks (объект-нормализованные)
- `ldm106_aligned.csv` — 106 landmarks после выравнивания на канонический ракурс
- `ldm106_original.csv` — 106 landmarks в пикселях исходного изображения
- `ldm134_raw.csv`, `ldm134_aligned.csv`, `ldm134_original.csv` — то же для 134 landmarks
- `texture.json` — текстура кожи: качество, аутентичность, метрики
- `face_mask.png` — маска лица (визуализация)
- `uv_texture.png` — UV-текстура (визуализация)
- `original.jpg` — исходное изображение
- `thumb.jpg` — thumbnail
- `face_crop.jpg` — вырезка лица
- `mesh.obj` / `mesh.mtl` — 3D-меш лица
- `reconstruction.npz` — параметры 3D-реконструкции
- `validation.json` — статус валидации

### stage1/photo_timeline_row.csv — строка из main_timeline.csv

Одна строка CSV с этой фотографией. Показывает, как выглядит запись в общей хронологии.

### stage1/stage1_manifest.json — манифест всего прогона Stage 1

Общая статистика: сколько фото обработано, сколько ошибок, время выполнения, устройство, модель.

### stage2/ — пример анализа пары

Пара: `1999_09_01__fdfba9d7bcd5` (frontal) vs `1999_10_01__cb6d8a56080e` (frontal)

**Файлы:**
- `pair_metrics_sample.csv` — одна строка из `pair_metrics.csv` со всеми 222 колонками
- `analysis_manifest.json` — общая статистика Stage 2
- `pair_details_sample.json` — детали по этой паре: zones, calibrated_metrics

### stage3/ — финальный отчёт

- `report_data.json` — полный отчёт Stage 3: narrative, timelines, change_points, zones, motion_maps

## Как это использовать

1. **Дизайнер:** откройте `info.json` — это главный файл карточки фото. Откройте `pair_metrics_sample.csv` — это строка таблицы сравнения. Посмотрите, как называются поля, какие типы значений (float, string, boolean, array).
2. **Разработчик:** эти файлы — реальные примеры того, что возвращает API. Подключите их вместо моков, чтобы проверить, как интерфейс работает с production-данными.
3. **Эксперт по предметной области:** здесь вы можете увидеть все метрики, которые система производит, и решить, какие из них нужны в отчёте.

## Важно

- Эти файлы — **реальные результаты**, не моки. Они показывают точную структуру, которую возвращает бэкенд.
- Файлы большие (`mesh.obj` — 7 MB, `reconstruction.npz` — 4.9 MB, `uv.npz` — 2.7 MB). Это нормально — они содержат 3D-геометрию.
- `face_mask.png` и `uv_texture.png` — визуализации для интерфейса. Они показывают, как система "видит" лицо.
