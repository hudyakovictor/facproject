## №7 (94) — доступность модальных окон

**Было:** ни одно из шести перекрывающих окон не объявляло себя диалогом.
Для клавиатурного и screen-reader пользователя это означало:

* Tab уводил фокус под оверлей — в невидимую часть страницы;
* screen reader продолжал читать фон как активное содержимое;
* после закрытия фокус терялся в начале документа, а не возвращался
  на кнопку, которой окно открыли;
* Escape обрабатывался только глобальным хендлером в `App.tsx`, который
  заодно сбрасывал выбранное фото — закрыть окно, не потеряв контекст,
  было нельзя.

**Стало:** хук `ui/src/useModal.ts` — focus trap, Escape, возврат фокуса.

| Окно | Роль | Почему так |
|---|---|---|
| `SettingsModal` | `dialog` + `aria-modal` | Полноэкранный оверлей, фон недоступен |
| `FullPhotoOverlay` | `dialog` + `aria-modal` | То же |
| `ProvenancePopup` | `dialog` + `aria-modal` | То же |
| `FilterPanel` | `dialog` + `aria-modal` | То же |
| `ComparisonPanel` | `region` + имя | **Не модалка:** занимает нижнюю треть, фон рабочий |
| `SourcesPanel` | `complementary` + имя | **Не модалка:** боковая панель, фон рабочий |

Последние два — сознательное отступление: пометить `aria-modal` панель,
поверх которой можно работать, значит соврать screen reader'у. Они получают
имя региона и закрытие по Escape, но не запирают фокус.

Хук слушает `keydown` в **capture-фазе**, поэтому перехватывает Escape
раньше глобального обработчика: окно закрывается, выбор фото сохраняется.

WCAG: 2.1.2 (No Keyboard Trap), 2.4.3 (Focus Order), 4.1.2 (Name, Role, Value).

### Дефект, найденный при написании тестов

Первая версия фильтра видимых элементов использовала `offsetParent !== null`.
В jsdom `offsetParent` равен `null` **для любого** элемента — фильтр
отбрасывал весь диалог, и focus trap молча переставал работать. Тесты это
поймали (3 из 8 упали).

Заменено на проверку `hidden`/`aria-hidden`. Геометрические проверки в
такой функции недопустимы: они делают поведение непроверяемым, а значит
уверенность в работе focus trap — необоснованной.

## №23, 24 (90) — печатный отчёт вместо `document.write`

**Было** (`App.tsx:267`):

```js
const w = window.open("", "_blank");
w.document.write(`<pre ...>${...}</pre>`);
```

Три проблемы:

1. **Инъекция разметки.** Подписи событий вставлялись конкатенацией без
   экранирования. Символ `<` в источнике ломал документ; `<script>` —
   исполнялся бы.
2. **Устаревший API.** `document.write` после загрузки страницы помечен
   как deprecated и в части браузеров игнорируется — окно оставалось
   пустым без единого сообщения.
3. **Нечего печатать.** `@media print` отсутствовал: тёмная тема на бумаге
   нечитаема, таблицы рвались между страницами.

**Стало:** `buildPrintReport()` + `openPrintReport()` в `ui/src/export.ts`.

* Все данные проходят `escapeHtml`;
* документ отдаётся через Blob-URL, а не `document.write`;
* `@media print`: светлая тема, `page-break-inside: avoid` для строк и
  карточек, `thead` повторяется на каждой странице, `@page { margin: 16mm }`,
  URL раскрываются текстом;
* демо-срез получает баннер «Демонстрационные данные» — бумажную копию
  нельзя переспросить о происхождении;
* блокировка всплывающих окон возвращает `false`, и пользователь видит
  причину вместо тишины.
