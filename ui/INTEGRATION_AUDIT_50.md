## 🔴 Критические

### D1. Настройки градиента молча стираются

`app6/api/settings.py:101`

```python
merged = {**DEFAULT_SETTINGS, **payload, "schema": SETTINGS_SCHEMA}
```

Слияние поверхностное. `SettingsModal` отправляет объект, собранный по типу
`AppSettings`, а в этом типе **нет поля `gradient`** (D2). Проверка:

```
после сохранения градиента:            max_reference = 0.99
после сохранения из SettingsModal:     max_reference = 0.12   ← ПОТЕРЯ
```

Пользователь настраивает градиент в `GradientEditor`, затем открывает
настройки и меняет любой ползунок — вся настройка градиента сбрасывается
к умолчаниям. Без предупреждения.

**Исправить:** рекурсивное слияние в `save_settings`.

### D2. `gradient` отсутствует в типе `AppSettings`

`ui/src/api.ts` объявляет 6 полей из 7. `HeatmapWorkbench` вынужден читать
его через `(settings as unknown as { gradient?: unknown })`. Это и причина
D1: поле, которого нет в типе, теряется при любом round-trip.

### D3. `load_settings` отдаёт поверхностную копию

`app6/api/settings.py`: `return dict(DEFAULT_SETTINGS)`. Вложенные словари
общие с константой модуля. Проверка:

```
DEFAULT_SETTINGS.gradient.stops[0].color до:     #1d4ed8
после мутации возвращённой копии:                #XXXXXX   ← испорчен глобал
```

Любой код, изменивший результат `load_settings`, портит умолчания **на
весь процесс**. Это ровно тот класс дефектов, который трудно диагностировать:
эффект проявляется в другом запросе.

**Исправить:** `copy.deepcopy(DEFAULT_SETTINGS)`.

### D4. `evidence_state` — главный вывод — спрятан в таблицу

`key_catalog.category_for("evidence_state") → ("A", "header")`.

Итоговое состояние доказательности по паре рендерится **строкой в таблице
ключей внутри вкладки «Статзначимость»**, наравне с `mt_p_approx`. При этом
шапка `PairCompareView` показывает только `status` сравнения
(measured/pose_mismatch) — технический статус измерения, не вывод.

Оценка размещения: **40/100**. Ключ присутствует, но читается последним,
хотя должен читаться первым.

**Исправить:** вынести группу `header` (`evidence_state`, `status`,
`pose_bin`, `pair_type`) в заголовок панели над вкладками.

## 🟠 Существенные

### D5. `pair_type` виден только на экспертном уровне

Категория G → `detail_level: expert`. Но `adjacent` и `baseline` — это
**разные вопросы**: «что изменилось между соседними кадрами» против «что
изменилось относительно базовой линии». В эталонном прогоне 13 adjacent и
12 baseline пар, и без метки числа несопоставимы.

Оценка: **35/100** — ключ в месте, где его по умолчанию не увидят.

**Исправить:** перенести `pair_type` и `pair_id` в группу `header` (D4).

### D6. Пять ключей дублируются в двух панелях

`ldm106_rmse`, `ldm134_rmse`, `p95_point_z`, `median_point_z`,
`significant_point_count` показываются и в `MetricsTable` (правая колонка),
и в `PairKeysPanel` → категория D. Значения приходят из разных эндпоинтов
(`/compare` и `/pairs/.../metrics`) и **могут разойтись**: первый считает
на лету, второй читает Stage 2.

**Исправить:** пометить источник в обеих панелях либо убрать дубли из
`MetricsTable`, оставив его для каналов, которых нет в Stage 2.

### D7. `PairKeysPanel` грузится до нажатия «Сравнить»

Условие рендера — `photoAId && photoBId`, они заполнены с монтирования
(первые два фото списка). Пользователь листает селектор — на каждое
изменение уходит запрос метрик пары, которую он не запрашивал.

**Исправить:** рендерить после `result`, как остальные панели.

### D8. Шапка переполняется на минимальном экране

Расчёт при 1024px (нижняя граница поддержки, ниже — баннер):

```
лого 200 + поиск 200 + навигация 804 + обновить 90
+ статус 190 + миниатюры 120 + кнопки 180 = 1784 px
переполнение: 760 px
```

Контейнер навигации — `overflow-hidden`, то есть режимы **ПРОГОН**,
**ОТЧЁТ**, **ДАННЫЕ** (добавленные последними) на 1024px просто обрезаются
без индикации.

**Исправить:** `flex-wrap` либо горизонтальный скролл навигации с явными
стрелками.

## 🟡 Умеренные

### D9. Категория `D` во вкладке «КАДР» почти пуста

`PhotoKeysPanel only={["C","H","D"]}`, но для Stage 1 категория D — это
единственная группа `contract` (2 ключа). Отдельный заголовок ради двух
служебных полей.

**Исправить:** перенести `landmark_contract` в H или показывать без
заголовка категории.

### D10. Служебные пути как «данные»

`mesh_file` и `motion_file` — относительные пути к `.npz` — образуют
собственные группы «Артефакт» из одного ключа. Они не для чтения
пользователем, а для загрузки артефакта.

**Исправить:** превратить в кнопку скачивания либо скрыть за экспертным
уровнем.

### D11. Пустая группа `F/date`

`date_status` на эталонном прогоне пуст всегда → группа «Дата» с
единственным `—`.

**Исправить:** группа из одного ключа должна вливаться в соседнюю.

### D12. `/api/v1/compare/upload` без потребителя

Единственный эндпоинт без клиента. Позволяет сравнить загружаемое фото с
уже извлечённым — сценарий из ТЗ, недоступный из интерфейса.

  ли ключ в момент принятия решения».
