## Ключевое решение: только геометрические подписи

`app6/stage2/core.py` содержит прямой отказ:

```python
"""Nine reproducible coordinate zones; avoids unverified anatomical labels."""
"warning": "Coordinate zones are not anatomical labels."
```

Порядок 106 точек 3DDFA нигде в репозитории не задокументирован. Подписать их
«кончик носа», «угол глаза» по памяти означало бы внести непроверяемые
утверждения в forensic-инструмент вопреки `AGENTS.md`.

Поэтому точки подписываются как **`LM-042` + координатная зона**, и панель
прямо сообщает пользователю, почему нет анатомических имён.

## Доработки бэкенда

`POST /api/v1/compare` теперь отдаёт на каждую точку:

* `x,y,z` — позиция в кадре A;
* `bx,by,bz` — позиция B **после Kabsch-выравнивания** в систему координат A
  (основа морфинга);
* `dx,dy,dz` — знаковое смещение: показывает **направление** ухода точки;
* `zone` — координатная зона, `visible` — признак измеримости;
* `zone_policy` — явное указание, что зоны не анатомические.

**Невидимые точки больше не выбрасываются.** Раньше они молча исчезали из
`heatmap_points`, и на карте это читалось как «точка совпала». Теперь они
приходят с `residual: null` и показываются как «нет данных».

### Побочно найденный дефект

Файл настроек, сохранённый прежней версией, **скрывал новые секции**:
`load_settings` возвращал его как есть, поэтому `landmark_shift` приходил
как `null`, и пороги классификации молча исчезали бы у любого, кто уже
пользовался приложением. Добавлено слияние с умолчаниями (пользовательские
значения сохраняются), закреплено тестом.

## Функционал панели

### Классификация по силе смещения

| Класс | Цвет | Условие |
|---|---|---|
| В пределах допустимого | зелёный | `residual ≤ tolerance` |
| Среднее смещение | жёлтый | `tolerance < residual ≤ suspect` |
| Аномальное смещение | красный | `residual > suspect` |
| Нет данных | серый пунктир | точка не видна на одном из кадров |

### Настраиваемые пороги

Два слайдера (`tolerance`, `suspect`) сохраняются в настройки бэкенда, чтобы
калибровка не терялась между сеансами. Пороги **честно помечены как
неподтверждённые калибровкой** — значения по умолчанию это стартовая точка, а
не установленная норма: допустимый разброс зависит от ракурса и качества
съёмки.

### Морфинг A→B

Ползунок переводит точки из положения на фото A в положение на фото B
(линейная интерполяция по выровненным координатам). При `t > 0` рисуется след
смещения от исходной позиции — видно и величину, и направление ухода.

### Два вида

* **Проекция** — фронтальная X-Y раскладка; размер точки пропорционален
  смещению, цвет — классу. Клик по карточке класса подсвечивает только его.
* **Таблица** — сортировка по смещению / номеру / зоне, знаковые `Δx/Δy/Δz`.

### Сводка по зонам

Показывает, где сосредоточены аномальные точки: число аномальных и медианное
смещение на зону, отсортировано по проблемности.

**Доля аномальных считается от ИЗМЕРЕННЫХ точек**, не от всех: включение
невидимых в знаменатель занижало бы выраженность расхождения.

## Оставшийся долг

1. **Хронология одной точки** — график поведения выбранной точки по всему
   архиву внутри одного ракурса. Требует серии сравнений, не одной пары.
2. **Рейтинг стабильности точек** по всему набору (какие точки костные, какие
   шумят от мимики) — тоже нужен пакетный расчёт на бэкенде.
3. **Калибровка порогов** по калибровочному набору: сейчас `calibrated: false`
   всегда, автоматического подбора нет.
4. `vertex_index` (привязка точки к вершине BFM) есть в артефактах Stage 1, но
   через API не отдаётся — пригодится для связи с UV-текстурой.
