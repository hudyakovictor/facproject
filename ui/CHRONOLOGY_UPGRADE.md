## Этап 1 — Достоверность (34 → 62)

### 1.1 Контракт `era` (+12)

**Было:** API отдаёт `DEMO_SEGMENT_1..5`, UI ждал жёсткий union `ERA_*`.
Условие `filters.eras.has(p.era)` отбрасывало **все 520 фото** — таймлайн
против живого бекенда был пуст, без единой ошибки на экране.

**Стало:** оказалось, что бекенд **уже** возвращает `era_meta` — контракт
менять не пришлось, нужно было его использовать.

* `Era` — открытый `string`; `buildEraMeta()` строит сегменты из ответа,
  детерминированная палитра, границы из дат при отсутствии `era_meta`;
* фильтр эпох переинициализируется фактическими сегментами;
* `validatePhoto()` заменил `isPhoto()`: проверяет типы, принадлежность
  `bucket` к 9 нормативным ракурсам и `era` к `era_meta`, возвращая **причину**
  отказа;
* отвергнутые строки показываются баннером `role="alert"`, а не теряются.

### 1.2 `REF` из реальных данных (+10)

**Было:** `export const REF = refMedians()` — модульная константа из
встроенного демо-набора, никогда не пересчитываемая. Все z-score сравнивали
реальные метрики с медианой синтетики.

**Стало:** `ui/src/baseline.ts` + React-контекст.

* базовый сегмент — **самый ранний** по времени (H0 проверяется относительно
  наиболее раннего состояния, а не всего набора, который может уже содержать
  подмену);
* разброс — робастный `1.4826·MAD` вместо σ: один плохой кадр больше не
  раздувает норму и не «съедает» реальные аномалии;
* при `n < 8` z-score **не показывается вовсе** — недостаток данных это
  `inconclusive`, а не число;
* в строке состояния виден источник базы, сегмент и размер выборки.

### 1.3 Ось X по времени (+6)

**Было:** `x = (index - offset) * thumbSize`. Разрывы 0…219 дней выглядели
одинаково, наклон линии не означал скорость.

**Стало:** две шкалы с переключателем **«ПО ДАТЕ / РАВНОМЕРНО»**. В режиме
`time` позиция пропорциональна дате; `idxForX` выполняет обратное
преобразование через поиск ближайшего по времени кадра, поэтому наведение,
выделение диапазонов и панорамирование работают в обоих режимах.

## Этап 2 — Корректность (62 → 78)

### 2.1 Разделение по ракурсам (+9)

**Было:** 100% соседних пар в demo-наборе — разные ракурсы, соединённые одной
линией. Видимые «скачки» метрики были сменой угла съёмки.

**Стало:** линия **никогда** не пересекает границу pose bin — путь строится
посегментно (`M ... L ...` на каждый bin), заливка тоже. Сегмент из одного
кадра не образует линии. Добавлен селектор ракурса дорожек.

### 2.2 Кривая эмпирического тренда (+7)

`ui/src/trend.ts` — регрессия **Тейла — Сена** (медиана попарных наклонов):
устойчива к ~29% испорченных наблюдений, в отличие от МНК. Тренд считается
**только внутри одного pose bin** и рисуется пунктиром с полосой ±2σ.

⚠️ Подписан как «эмпирический тренд ракурса», **не** «модель старения» —
называть линию по наблюдениям биологической моделью было бы заявкой на
точность, которой нет.

## Этап 3 — Наглядность (78 → 88)

Новый модуль `ui/src/components/ComparePanels.tsx`:

| Панель | Что закрывает |
|---|---|
| **PhotoPair** | ТЗ «визуализацией обоих изображений рядом» — режим сравнения показывал только меш |
| **ZoneBreakdown** | 9 зон с `rmse` и **знаковыми** `signed_x/y/z` — отвечает «в чём различие», а не только «насколько». Зоны, исключённые по видимости, перечислены отдельно |
| **HeatmapLegend** | Градиент с числовой шкалой — карту стало возможно прочитать |
| **AlignmentDiagnostics** | `coverage`, якорные точки, отброшенные выбросы, остаток до/после — позволяет судить о доверии к числу |
| **MetricsTable** | Человекочитаемые подписи вместо `Object.entries` с 5 знаками; мимика (`alpha_exp`) явно отделена от идентичности |

Все эти данные бекенд **уже отдавал** — интерфейс их игнорировал.

**Единственная правка бекенда:** `GET /api/v1/photos/{id}/image?kind=...` —
отдаёт сохранённые Stage 1 изображения. `kind` — закрытый словарь, путь
проверяется на выход за пределы каталога; в demo-режиме честный 409.

## Этап 4 — Хронологические аномалии (88 → 92)

### 4.1 Подключены детекторы Stage 2 (+3)

Stage 2 давно считал то, что просило ТЗ, но **ничего не доходило до UI**:
`irreversible_return` (A→B→A), `baseline_return`, `biological_rate`,
`cumulative_drift`, `chronology_rate`.

`research_timeline.py` теперь пробрасывает сводки и проставляет флаг
`RETURN_TO_BASELINE` на кадрах затронутых лет. Панель `ChronologyAnomalies`
показывает их в режиме STATS с обязательной оговоркой «флаги требуют
независимой проверки».

**Побочная находка:** research-режим отдавал `era: "STAGE2_RESEARCH"` для всех
кадров — эпох не было вовсе. Теперь сегменты строятся по годам съёмки.

### 4.2 Связи A↔B (+1) · 4.3 Подписи осей Y (+1)

Дуги между кадрами выделенных диапазонов (цепочка соседних, не O(n²)-паутина;
лимит 60). Диапазон значений каждой дорожки подписан в левой колонке.

## Найдено и исправлено сверх плана

**Легенда роняла весь режим сравнения.** `heatColor()` из мока `three`
возвращал `undefined` → `TypeError` → пустой экран вместо панели сравнения.
Поймано существующими тестами `PairCompareView`. Легенда теперь деградирует до
нейтрального градиента, сохраняя верные числа шкалы: вспомогательная функция
цвета не должна убивать рабочий инструмент.

## Оставшийся долг (~8 баллов до 100)

1. **Вычитание калибровочного шума** — ключевая идея ТЗ. Кандидаты
   показываются (`Δ2.34°`), но разница не вычитается. Нужен расчёт на бекенде
   и решение: покомпонентно по зонам или единым скаляром.
2. **PDF-отчёт** с визуализациями (JSON-экспорт готов).
3. **Текстурные карты** FFT/альбедо/LBP — исключены из объёма заказчиком.
4. **`detail_level`** сохраняется, но не влияет на плотность информации.
