## Дополнительно найденные проблемы, не относящиеся напрямую к E1–E10

### Высокий приоритет

1. **`app6/archive_adapter.py` несовместим с заявленным Python 3.11.**
   `safe_extract_archive()` вызывает `TarFile.extractall(..., filter="data")`. В Python 3.11 этот keyword не поддерживается; позитивный тест извлечения падает с `TypeError`. До исправления безопасный сценарный импорт TAR не работает. Исправление должно сохранить fail-closed проверку обхода путей/ссылок и добавить разрешение только regular files/directories перед вызовом совместимого extract.
2. **`app6/api/compare.py::full_mesh_compare()` загружает BFM до проверки `alpha_id`.**
   При нечисловом `alpha_id` функция должна вернуть `None`, но при недоступной модели сначала падает `FileNotFoundError`. Проверку finite alpha нужно выполнять до `load_bfm_model()`.
3. **Тест `app6/test_module/test_a11_artifacts.py` не собирается.**
   Он импортирует `tools.rebuild_landmark_utility` из `.runtime`, но `.runtime/` отсутствует и намеренно игнорируется Git. В результате полный тестовый набор не является самодостаточным.

### Контрактные расхождения

- API Stage 3 теперь требует `report_meta.json` + `report_sections/`, но несколько тестов всё ещё создают устаревший `report_data.json`; из-за этого падают health/report tests. Нужно либо удалить legacy-ожидания из тестов, либо явно поддержать старый формат.
- `evidence_state()` отдаёт `quality_limited` даже для статуса `within_reconstruction_noise`, а один тест ожидает `within_noise`. Это не однозначный кодовый дефект: тест и приоритеты, заданные в `evidence.py`, расходятся; требуется решение о семантике.
